# 11-03｜原子包裝與連續工作

**狀態：遊戲設計規格稿｜一般連續性與例外可供分段交接；權利切換及交接完成邊界仍待確認，未經模擬驗證**

[返回 11 總覽](11_餐廳經營系統.md)。包裝是員工連續工作的安排，不表示整道菜獨占，也不是可回滾所有成果的交易。本文件主導包裝生命週期與送餐配置，11-04 主導各階段權利。

## 一、玩家如何使用包裝

玩家希望員工連續處理同一道菜，可在排程板把「取放食材→烹飪→送餐」或「烹飪→送餐」這類合法區段列為工作項目，與接待或單獨烹飪一起安排優先度。員工進入找工作流程時，先選工作種類／包裝，再選符合資格的具體菜品。

選中包裝後，員工還沒有開始包裝。他必須取得第一項底層工作所需的階段權利，才進入包裝已啟動狀態。之後正常情況下維持同一菜品的連續工作，玩家即使看到櫃台新增更高優先接待，員工也不會立刻轉身離開。

玩家仍可能看到接力：另一人取得下一階段的有效權利，原員工不能憑「我正在包裝」接手，競爭失敗便結束包裝、重新找工作。已完成的備料或料理留在世界中，不會因這次結束而消失。這種結果呈現的是階段競爭與協作，不等於包裝設計承諾從頭到尾都由同一人完成。

主角不適用包裝強制延續；能手動做符合前提的工作，仍不能打斷已取得的實際執行權。工作途中營養不足、睡眠等特殊情況另待 08／09 協調，不用一般包裝規則替其定案。

## 二、合法性、選擇與啟動

### 2.1 合法區段與綁定

包裝僅能由同一固定流程內連續工作構成，不能跳過必要階段、跨菜品／訂單，也不能把接待與洗碗任意接在一起。選中某份甲菜的包裝後，其連續執行範圍是該份甲菜，不是做完甲菜取料後改做乙菜烹飪。

取放食材的底層拆分仍待 11-01 定義，因此例子使用目前的業務階段名稱，不據此預先指定每個移動與取放動作的不可中斷區間。包裝也不會同時預留全部設備，或一次取得後續所有預先權。

### 2.2 選擇與啟動是兩個事件

員工依資格與優先度選到包裝及菜品，只形成目標意圖。若第一項是烹飪，而取料尚未開始，烹飪預先權尚未開放，員工不能靠選擇直接啟動包裝。此時等候也不能標成「包裝進行中」。

待取料開始、烹飪階段權利開放，員工參加競爭並成功取得第一項所需階段權利後，包裝才啟動。即使已啟動，前置若未完成仍不得實際烹飪。這使「包裝啟動」「底層工作開始」「後續權利開放」可能是不同時點，不能壓成同一個開始事件。

原交接包以取得首項階段權利為門檻；未開啟預先權、直接取得首項實際工作時的精確包裝起點，以及操作確認取消後包裝保留或結束，仍屬 U11-04。這不是要求玩家所有包裝都必須開預先權。

### 2.3 包裝的狀態轉換

| 狀態 | 可確定的行為 | 接下來的判斷 |
|---|---|---|
| 已選擇、未啟動 | 有菜品與連續區段意圖，沒有包裝連續性保障 | 首項權利何時開放、能否取得；等待期間改選細則未定 |
| 已啟動、尚待實際工作 | 已取得首項所需階段權利；不等於底層動作已做 | 前置、資源及實際取得條件；持權等待依 11-04 |
| 目前底層工作在確認／執行 | 已有實際執行權，不得被其他人搶走 | 確認可取消的共通規則保留；正式執行一般須完成 |
| 目前工作完成、尚有包裝階段 | 保留成果，追求同一菜品的下一階段 | 該階段權利、資源、人工改排及中斷例外 |
| 正常完成 | 已完成所包連續區段，無需維持該包裝 | 回到可選下一工作狀態；送餐交接型的精確完成點另待補 |
| 例外結束 | 放棄繼續原包裝，不回滾成果 | 回到找工作流程；未處理權利、成品位置等按未決邊界處理 |

## 三、階段競爭、延續與例外結束

### 3.1 一般連續路徑

包裝已啟動後，只要沒有例外，員工繼續下一個必要階段，即使有個人優先度更高的工作出現也不改選。每到新階段仍須滿足前置及資源條件，並取得對應權利；上一階段成功不保證下一階段成功。

前置階段開始後，下一階段可開放預先權；原員工與其他合格員工都受同一階段規則約束。若別人已有有效預先權，原員工不能以包裝連續性覆蓋它。若工作已由任何角色取得實際執行權並進確認／正式執行，後來主角或較高順位員工也不能取代。

正常做完最後一項底層工作後，包裝不再要求員工延續這份菜。對「烹飪→送餐」直送且沒有交接爭議的路徑，可追蹤至送餐完成；對交接策略，原員工放桌、接手者取得或送達究竟何時算原包裝完成，現有資料沒有唯一答案。

### 3.2 哪些事件能結束包裝

| 事件 | 必要前提與處理 | 不可推論 |
|---|---|---|
| 較高優先工作出現 | 無其他例外時繼續包裝 | 不可直接以優先度搶占 |
| 階段預先權競爭失敗 | 目標階段權利未取得；放棄目標並結束包裝 | 不撤銷已完成取料或料理 |
| 持有階段預先權但實際競爭失敗 | 如主角在仍可介入的階段取得工作；放棄目標並結束包裝 | 不表示別人能搶掉已確認／正式執行的工作 |
| 訂單板人工修改鎖定安排 | 修改影響包裝鎖定菜品時，下一工作邊界生效並結束包裝 | 不立即停掉目前底層動作 |
| 下一項資源暫時被占用 | 檢查有無更高優先、已授權且可執行工作；有則可結束包裝轉做，沒有則等資源 | 不把資源等待當競爭失敗，不把較低優先候選當這個例外的依據 |

底層正式動作須先完成，才換工作或延續包裝。若下一階段權利已在目前動作期間輸掉，是否立即標記包裝結束或先標記將結束，交接包未定義精確標記時點；可確定的是目前動作不因此消失，下一階段不能繼續，成果保留。資訊呈現不得把「將不再延續」寫成目前動作已取消。

### 3.3 區分兩類等待與權利清理

持預先權等待前置完成，原則上等待、不另找工作。下一階段所需資源被占用，才有本章的較高優先工作檢查。若前置等待與資源占用同時存在，哪個條件先判斷、是否適用包裝例外仍須確認，不能把所有等待概括成可轉做。

逾時釋權並重新排程是 11-04 的方向；逾時與資源例外或人工修改同刻發生、包裝結束時其餘權利的清理順序尚未定。不允許藉此新增永久持權或任意重用成果，也不能假定包裝結束會自動完成成品放桌、轉交或設備釋放動作。

## 四、烹飪後如何送餐

### 4.1 適用門檻

只有包含連續「烹飪→送餐」的原子包裝，才可設定繞過送餐桌直接送餐。單獨烹飪與只包到烹飪者，完成後須放送餐桌。這是成品如何銜接下一實際工作的規則，送餐桌本身不是每道菜必須再經過的固定工作階段。

三種策略都保留供玩家配置與比較，沒有選定唯一最佳策略。主角不適用員工包裝，卻又涉及上述直送門檻；主角手動操作的適用方式仍見 U11-09，不自行增加主角例外。

### 4.2 完成後直送

員工完成烹飪後，若依規則能取得送餐工作、資源與實際條件成立，就接續同一菜品送餐，不經送餐桌。取得送餐實際執行權仍須進確認與正式動作；「直送」沒有免除移動與工作時間。

若送餐權利已被他人有效取得，不能以直送配置保證原員工勝出。這時需依階段競爭結束包裝；成品如何落地或交給權利持有者、直送模式是否允許他人提前預選等完整銜接仍未定，不能把可直送寫成必定直送。

### 4.3 可提前預選交接，否則直送

此配置允許其他員工透過通用預先權提前爭取送餐。烹飪尚未完成時，接手者可在開放條件成立後取得權利並等待，但不能先搬走成品。烹飪完成、交接成功後，由接手者做後續送餐；這是配置允許的協作，不能把原烹飪者一律記作競爭失敗。

未發生交接時，方向是原員工直送，仍須滿足實際取得與資源條件。可是「沒人預選」與「有人預選但已逾時／未抵達／交接失敗」不是同一情況。後三者何時回退直送、原員工何時重新競爭、原包裝何時完成尚未定，不能在任何交接問題發生時自動回退。

### 4.4 完成後送餐桌交接

員工完成烹飪後將成品放到送餐桌，再銜接接手者送餐。成品已到桌代表烹飪成果可供後續使用，並不表示已送達或已歸某員工。接手者依資格、有效預先權及實際競爭取得送餐工作，確認與正式執行後才送達。

送餐桌被占用時不能假定可無限堆放；其容量與滿載處理未定。放桌包含在哪個底層動作、由誰搬運及原包裝在哪個事件正常完成，均須補規格。不能為了閉合包裝狀態而擅增一項固定交接工作。

## 五、可追蹤的包裝情境

### 5.1 啟動後等待，再連續完成

**起始狀態：** B 已選甲菜的「烹飪→送餐」包裝、具有兩項資格並啟用烹飪預先權；A 正處理甲菜取料。取料已越過「開始」界線，烹飪權利已開放。沒有其他競爭，本例不發生逾時、人工修改或資源阻塞。

1. B 成功取得烹飪預先權，包裝此時啟動；甲菜仍在取料階段，B 仍未烹飪。訂單板須保留 A 的目前進度，不能改成 B 執行中。
2. A 完成取料，成果留在烹飪桌。B 依實際條件與到點請求取得烹飪執行權，經確認後正式製作；該階段預先權依「實際開始後釋放」原則處理，精確與確認對齊點仍屬 U11-04。
3. 烹飪期間即使新增較高優先接待，B 仍繼續。設定本例送餐沒有他人有效權利與競爭，資源保持可用，採直送配置。
4. 烹飪完成後 B 取得送餐實際工作，確認、移動與送餐完成，甲菜送達，包裝連續區段完成。

此例證明包裝可從「已啟動但等待」走到正常完成；不能用它推定所有烹飪者必然有送餐權。

### 5.2 資源阻塞時的分支

**起始狀態：** A 已啟動料理包裝，完成甲菜目前底層工作，正要接續下一階段；本例明定沒有他人取得該目標階段的有效權利。所需設備卻正在服務別份工作。

A 必須先辨識這是設備占用，不是甲菜階段已輸給別人。若 A 同時獲准接待、接待高於包裝且當下確實可執行，規則允許在此邊界結束包裝轉接待；若沒有此類工作，就保留包裝等待資源。原設備使用者不受影響，甲菜已完成成果不回滾。若問「符合可轉做條件時是否必然立即切換」，原規則僅表達允許，尚需確認自動選擇時機，不能以本例擅定。

## 六、資訊、缺口與可交接程度

玩家需能辨識已選未啟動、包裝已啟動、目前底層動作、等待原因、下一階段受阻及結束原因。訂單板可承接料理資訊，但如何呈現階段權利與包裝意圖交 13；不能只用一個「忙碌」標籤隱去差別。

第二至三章的一般生命週期、不能搶占與失敗不回滾，以及第四章三策略的適用條件已可交接為需求原則。完整可執行規格仍缺：首項未用預先權時的啟動點、確認取消、前置與資源同時等待、允許轉做時的實際選擇時機、權利清理、成品位置及交接型正常完成點。這些分別影響包裝顯示、角色下一動作及送餐責任，不能用預設值補齊。
