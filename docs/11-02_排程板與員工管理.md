# 11-02｜排程板與員工管理

**狀態：遊戲設計規格稿｜選擇層級與授權邊界可供分段交接；候選間完整排序仍未定，未經模擬驗證**

[返回 11 總覽](11_餐廳經營系統.md)。本文件說明玩家如何設定員工，以及員工在什麼條件下尋找下一工作。它負責「想做什麼」，不以工作優先度取代 11-04 的「誰取得工作」。

## 一、玩家從配置到觀察的過程

玩家觀察餐廳後，可能發現櫃台有人排隊、備料已完成卻沒人烹飪，或員工都在等同一設備。玩家開啟排程板，選擇要調整的員工，設定他可做的工作種類與菜色，再安排個別工作優先度、製菜偏好及各工作預先權開關。設定是授權與選擇依據，不是對每份菜的即時所有權宣告。

管理配置期間依 08 全世界暫停，角色動作與背景活動保留進度。恢復後，員工依自己的狀態繼續：正在正式執行者先完成動作；正在包裝者遵守連續性；持有預先權等待前置者依持權規則等待。只有進入可重新選擇工作的狀態，才按新的候選與排序尋找目標。授權撤銷等設定如何作用於已持權或操作確認中的員工仍未完整定義，不能把「管理時可修改」當成「立即停止目前動作」。

玩家接著從員工移動、等待、實際接手及訂單板進度觀察配置效果。若 A、B 都有烹飪資格，他們可以選擇同一道菜並發生競爭；選中後仍可能失敗，不能預先把整份菜固定分給其中一人。玩家想改某人下一份具體菜品時，使用 11-05 的訂單板操作，其效果仍受資格、權利與工作邊界限制。

## 二、各項設定回答不同問題

| 術語 | 玩家設定或判斷的內容 | 不代表什麼 |
|---|---|---|
| 工作資格 | 該員工獲准做哪些工作種類／合法包裝 | 有需求時必然可立即執行 |
| 菜色資格 | 該員工可處理哪些菜色 | 該菜已備妥食材、設備或已分配給他 |
| 工作優先度 | 同一員工比較自己不同工作或包裝的先後 | 可拿不同員工的優先度數字比較勝負 |
| 製菜偏好 | 選定料理工作種類後，挑哪份具體菜品的依據 | 能跳過工作資格、必要前置或別人的有效權利 |
| 隱性候選 | 已授權包裝內、未另外顯式排列的底層工作候選 | 可以做任何未授權工作 |
| 員工排序 | 多人競爭同一階段時的角色順位 | 本人多個候選工作之間的完整排序 |
| 預先權開關 | 每位員工每項工作是否參與提前權利競爭 | 已成功持有權利或已開始工作 |
| 工作選擇 | 員工選出要追求的工作種類與具體目標 | 已贏得預先權或實際執行權 |
| 重新排程 | 放棄原目標後，重新檢查授權候選與當下條件 | 重做、撤銷或重新分配已完成工作 |

主角是唯一可直接操控在空間移動的角色，可手動執行符合實際條件的工作。排程對主角只是預設建議，不能把員工授權清單當成主角操作禁令；主角仍不能搶走已取得的實際執行權，或跳過前置及資源條件。關閉主角自動工作選擇仍屬候選設定。原子包裝的強制連續性只適用員工。

員工資格可重疊，工作與菜色資格須一起考量。例如有烹飪工作資格但未獲某菜色資格的員工，不能只因烹飪優先度很高就處理該菜。一般員工營養不足無法工作的方向保留，工作途中如何停止則由 08／09 協調；機器老鼠不需食物營養，不能因此推定具備全部工作資格。

## 三、顯式項目、包裝與隱性候選

玩家可把單獨工作與合法原子包裝放在同一個人的顯式優先度安排中。例如「接待」可排在「取放食材→烹飪→送餐」包裝前。這代表該員工重新選工作時的偏好；包裝已啟動後，不因新接待出現就照此排序中途切換。正常包裝延續及資源阻塞例外見 11-03。

若包裝所含烹飪沒有另外顯式排列，烹飪仍可作為隱性候選，低於顯式項目。若已單獨列出烹飪，便有顯式優先度可用，不應再因它也存在於包裝中而默默建立另一份同一實際工作。候選如何去除重疊、如何表達包裝與單項授權的聯動仍須規格化；此處不指定實作方法。

「低於顯式」只能決定層級，尚不能處理所有選擇。若高順位顯式包裝尚不能啟動，但其中的較低順位隱性烹飪可以執行，現有資料沒有完整定義要保留原包裝選擇等待、略過它，或何時重新檢查。不能直接補成永遠等最高項，也不能宣告所有不可立即執行項目一律略過，因為預先權本來就允許提前等待。

交接包另有「隱性競爭依員工排序」方向，應保留其多人競爭意義。對同一員工而言，若同時出現多個隱性候選，員工排序無法替他比較自己的兩份工作。隱性候選彼此、顯式同順位及重疊包裝的完整先後尚未定。

## 四、員工如何尋找下一項工作

### 4.1 先判斷是否進入重新選擇

| 員工目前狀態                    | 應如何處理                          |
| ------------------------- | ------------------------------ |
| 正式執行底層工作                  | 保持執行直到完成；一般優先度變動不打斷            |
| 已取得實際執行權，仍在確認             | 執行權已受保護；確認取消沿用 08，設定變更的作用方式尚待補 |
| 已啟動包裝，沒有例外                | 追求包裝下一階段，不回到一般工作優先度挑選          |
| 持有效預先權且前置未完成              | 原則等待，不因別項工作出現就重新找工作            |
| 競爭失敗、正常工作完成且無需延續的包裝，或原本空閒 | 進入一般工作選擇；包裝失敗先依其規則結束           |
| 沒有可執行的授權工作                | 等待並持續檢查條件；不能自動新增未授權的職責         |

已選包裝但未取得首項權利的等待，不屬於「已啟動包裝」。此時改選條件仍未完整定義，不能藉第一列包裝規則把它鎖住。

### 4.2 分層選擇與當下判斷

第一層是授權範圍：辨識員工可做的工作、合法包裝與菜色，並檢查角色能力。沒有授權的工作不因緊急、缺人或較有利而加入；菜品的食材與廚具資格另由料理流程檢查。

第二層是工作種類或包裝：按個別工作優先度比較顯式項目，隱性候選低於顯式。這一層選的是「接待、烹飪、某連續包裝」等項目，不先憑一份菜的位置決定整體工作種類。候選的可追求狀態須區分可實際執行、可競爭預先權後等待、尚未開放權利；各類如何一起篩選的未決分支見第三章。

第三層是具體目標：選擇料理工作後，再依製菜偏好或訂單板順序挑具體菜品。已有菜色資格仍不等於任何階段都可做；必要前置與當下權利必須重新判斷。兩種排序同時存在或出現平手時，目前無法推定哪個優先，因此僅在其指向相同目標或只有唯一候選的情境下可推出唯一選擇。

第四層是取得：對已選階段依預先權開放狀態與實際條件提出相應競爭。若勝出取得預先權但前置未完成，進入持權等待；取得實際執行權則進入操作確認；失敗則放棄該目標、重新檢查其他授權工作。工作優先度不會因他人順位較高而被系統擅改。

重新排程不是必須在同一瞬間無限重試原目標。重新檢查頻率、已知不可取得目標的排除與同刻重試次序仍待定，但不得因此重複取得工作或無因果產出。

## 五、可逐步推演的選擇情境

### 5.1 資格先於偏好，工作種類先於菜品

**起始設定：** A 空閒、沒有包裝與預先權；獲准接待及烹飪甲菜，未獲准烹飪乙菜。接待高於烹飪。此時有可接待顧客，甲菜已備料且設備可用，乙菜也在待做清單前方。本例不涉及滿座與平手。

1. A 先辨識授權：乙菜不能因訂單板排前面而進入 A 的烹飪目標。
2. 接待與烹飪都有符合本例條件的需求，A 依自己的工作優先度選接待；甲菜順位不取代工作種類選擇。
3. A 到接待工作位置提出實際請求；若無其他競爭與條件變動，取得後確認並接待。訂單板不把接待顯示成料理執行工作。
4. 接待完成後，本例設定已無待接待顧客，甲菜仍是唯一合格烹飪目標，A 才選甲菜烹飪。
5. 若此時 B 已持甲菜烹飪有效預先權，A 不能憑高烹飪優先度直接取得；須依競爭結果回到尋找工作。若沒有既得權或其他競爭、條件仍成立，A 才能取得實際工作。

**可推結果：** 此例能確定選擇層級，無法在不知道 B 的權利狀態時先決定烹飪者。資源與包裝在本例中分別為可用及未啟動，兩者不能從選擇行為自行生成。

### 5.2 多位員工優先度不能互相比勝負

**起始設定：** A、B 都空閒、具有甲菜烹飪資格並啟用該項預先權，無包裝。甲菜前置已開始，烹飪預先權已開放但尚無持有者；兩人都選了同一目標。B 的員工排序在 A 前，且無主角或實際工作競爭。

1. A 將烹飪列為個人最高優先；B 也選到烹飪，但它在 B 個人安排中未必最高。本例給定兩人都已選同一目標，不用跨人優先度倒推其選擇。
2. 兩人參與同一輪預先權競爭，由 B 的員工排序勝出。
3. B 持權等待前置完成；A 競爭失敗，放棄目標並重新排程，沒有包裝需要結束。
4. 訂單板不能把 B 顯示成已在烹飪。前置完成且實際條件成立後，B 才進一步取得實際工作；資源若占用，則仍有等待問題。

### 5.3 隱性候選的推演停止點

**起始設定：** A 獲准某料理包裝，其中烹飪與送餐都未另列顯式項目。當下沒有可執行的顯式工作，甲菜可烹飪、乙菜可送餐；A 沒有持權，也沒有已啟動包裝。

可以確定兩者都不能越過尚可選擇的顯式項目，也不能超出授權菜色；但目前無法確定 A 在甲菜烹飪與乙菜送餐之間選誰。缺少的是同員工多個隱性候選的排序，不是 A 與別人的員工順位。若尚有已選但未啟動的顯式包裝，還須先補其等待／改選規則。此例應停在候選辨識，不用隨機、最短時間或清單位置補答案。

## 六、資訊回饋與未決事項

排程板需讓玩家分辨工作與菜色授權、個人工作優先度、製菜偏好、隱性候選及員工排序，並區分「預先權開關啟用」與「當下實際持權」。前者是設定，後者隨競爭與釋放變動；顯示方式與位置由 13 細化，不要求新增獨立頁面。

| 尚缺規則 | 影響的判斷 | 協調入口 |
|---|---|---|
| 不可立即執行的顯式項目與可提前競爭／較低候選如何比較 | 等待最高項或轉做別項，尤其已選未啟動包裝 | 11-02／03／04 |
| 製菜偏好與訂單板順序的優先關係、平手 | 多個合格菜品中究竟選誰 | 11-02／05 |
| 同員工隱性候選與重疊包裝排序 | 無顯式可選時的唯一下一工作 | 11-02 |
| 包裝授權與單項資格聯動、撤銷生效 | 哪些候選仍合法，已持權者如何處理 | 08／11，U11-06／08 |
| 重試時機與條件更新 | 失敗／等待後何時再檢查，不在同刻無限重試 | 08／11-04，U11-05 |

第二至四章已可交接選擇層級、角色差異與一般分支；第五章可作需求討論及驗收情境。尚不能宣稱具備對所有員工狀態都產生唯一答案的完整排程規格。候選設定僅包含已提出的主角自動選擇開關，未決表格不表示採用了新策略。

依據：交接包決策摘要第 4、6、8 節與案例共同概念；01 GAME-18、05 第 2.4 節、06 第 5.2 節及 08 玩家配置權。尚未執行排程模擬或效率比較。
