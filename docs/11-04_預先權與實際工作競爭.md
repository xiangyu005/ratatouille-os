# 11-04｜預先權與實際工作競爭

**狀態：遊戲設計規格稿｜權利保護與主要競爭分支可供分段交接；同刻排序與權利生命週期邊界仍待協調，未經模擬驗證**

[返回 11 總覽](11_餐廳經營系統.md)。本文件負責誰能提前保有某個階段的工作機會、誰能真正執行，以及等待或失敗後如何處理。角色如何挑目標見 11-02；本文件不把個人工作優先度當成多人競爭順位。

## 一、玩家會看到的競爭與接力

玩家在排程板為 A 開啟某項工作預先權，只代表允許 A 提前參與競爭。當甲菜的前置工作開始，對應下一階段權利才可能開放。A 選定該階段並成功取得後，玩家可理解為「A 保有這個階段的工作機會」，尚不能視為 A 正在執行。

若前置仍未完成，A 原則上等待。其他員工即使已到工作位置，也不能因自己可以提出實際請求，就搶走 A 的有效預先權。主角仍有在實際工作取得階段介入的例外；但是只要任一角色已取得實際執行權、進入操作確認，即使尚未正式動作，後來的主角也不能取代他。

因此玩家可能看到 A 在取料、B 在等待烹飪，後來 B 接手製作；也可能看到 A 持烹飪預先權等待，卻在主角合法介入後放棄目標。兩種情況都不能讓同一底層工作被做兩次。已完成的備料或料理繼續存在，失敗者重新找工作只改變後續安排。

## 二、術語與權利狀態

### 2.1 製菜權、預先權及實際執行權

| 術語 | 確切意義與適用範圍 |
|---|---|
| 原先製菜權 | 早期討論用語，涵蓋取放食材與烹飪兩階段，不涵蓋送餐；不能據此推定整道菜歸同一人 |
| 通用預先權 | 後續擴展的階段權利概念，可配置於接待之後的工作階段，包含送餐及後續工作方向；各階段開放條件尚未全部完成 |
| 預先權競爭 | 對已開放階段爭取提前的工作機會；實際成功取得才有保障 |
| 有效預先權 | 已成功取得且尚未釋放或失效；保障特定目標階段，仍不是實際工作已開始 |
| 實際工作競爭 | 前置與實際條件成立後，爭取當下底層工作的執行權 |
| 實際執行權 | 08 定義的工作取得，取得後進入操作確認；確認與正式執行期間都不可被重複取得 |
| 資源等待 | 所需資源暫時不可用；不因等待就宣告目標階段競爭失敗 |
| 競爭失敗 | 未贏得目標預先權，或持有階段權利但未贏得實際工作；原目標放棄並重新排程 |

預先權的對象是特定菜品／工作目標的特定階段，不是全部菜色、整筆訂單或全部設備。兩人選同一道菜的不同階段，不必然構成同一階段權利衝突；是否爭用設備還須另外看資源條件。

### 2.2 不能用一個「已指派」涵蓋的狀態

工作選擇、預先權開關、預先權申請、有效持權、實際取得、操作確認與正式執行是不同資訊。選中菜品可以失敗；開關啟用可以尚無申請；持權可以尚在等待；確認中雖沒有正式產出，實際執行權已受保護。

「預先權已釋放」也不表示該工作重新空閒。可能是角色已開始實際工作，以實際執行權及執行狀態保護它。讀者需先看工作是否已取得或完成，不能只看預先權是否為空就允許新一輪重做。

## 三、階段開放與實際執行的時間關係

### 3.1 已確認的先後限制

前置階段開始前，下一階段預先權尚未開放；不能提前搶取。前置開始後，合格員工才可能對下一階段競爭預先權。取得者可在前階段執行期間等待，但真正開始下一工作仍需前置成果完成及實際條件成立。

實際工作開始後釋放該階段預先權，工作仍在自身時間內執行，不可再次競爭同一底層工作。前置的「開始」可讓下一階段提前準備，前置的「完成」才提供下一工作所需成果，兩者不能互換。

上述「開始」沿用交接包；08 則明定取得實際執行權、操作確認、正式執行三個相關時點。究竟在取得執行權或正式執行時釋放預先權、開放下一階段，仍屬 U11-04。以下推演若使用「已開始」，指情境已越過所需開始界線，不偷偷替這個界線選定實作時點。

### 3.2 從提前持權到實際工作

| 時段／事件 | 目標階段與角色行為 | 權利及資源判斷 |
|---|---|---|
| 前置尚未開始 | 可有工作意圖，但不能申請尚未開放的下一階段預先權 | 尚無該階段有效預先權；意圖不預留設備 |
| 前置已開始、尚未完成 | 開放對應階段預先權競爭 | 勝出者持權，其他競爭者失敗；不能使用尚未完成成果 |
| 持權等待 | 等前置完成，不一般性改選其他工作 | 持權不等於設備已保留；等待期限方向見第五章 |
| 前置完成 | 檢查角色能力、資源、位置與實際取得條件 | 有效預先權受保護，主角介入例外仍可能適用 |
| 取得實際執行權 | 角色進入操作確認 | 已有執行權者不可被後到角色取代，與預先權切換的精確時點待協調 |
| 正式執行 | 確認完成，執行自身工作 | 一般調度不可搶占；預先權釋放不使工作重開 |
| 完成 | 成果供後續使用，按工作規則釋放實際執行權與資源 | 不能重做已完成的同一工作；下一階段仍須各自符合條件 |

08 要求實際請求由主角在互動範圍、員工抵達工作定點提出。預先權競爭是否也要求到點、持權等待期間角色站在哪裡與如何移動，尚未定義。前置完成不代表等待者可瞬間到達設備。

首項取料如何從接待取得開放條件，以及通用預先權延伸至收盤／洗碗時的前置事件，仍待逐項設計；不能將料理範例機械套到所有工作。

## 四、競爭如何裁決

### 4.1 先辨識既有權利，再判斷新請求

| 當下事實 | 可確定的處理 |
|---|---|
| 該底層工作已取得實際執行權，在確認或正式執行中 | 不再讓後到角色取得，不因主角、高員工順位或預先權申請而改派 |
| 尚無實際執行權，但 A 已有有效預先權 | 未持權的其他員工不得競爭該工作的實際執行；主角實際介入例外保留 |
| 尚無有效預先權，實際競爭與預先權競爭同時發生 | 實際競爭優先；僅開啟開關或剛提出預先權請求不等於既得權 |
| 多名員工競爭同一目標階段的預先權 | 按員工排序決定勝出，不比較不同人的個別工作優先度 |
| 多個符合條件的實際請求衝突，且不違反上述既有權利 | 依 08：同輪判定主角優先，其餘家族員工與機器老鼠按玩家設定順序 |

此表是條件關係，不是完整同 Tick 排序演算法。不衝突工作可以並行；若共同爭用多個設備，完整複合資源裁決仍未完成。

### 4.2 「實際優先」的適用邊界

A 只有預先權開關啟用，尚未成功持權，B 同時對已可執行的工作提出實際請求，先處理實際競爭。若 B 符合條件並勝出，A 不能再取得同一工作來重做。反之，若 A 在此次新請求之前已有效持權，B 不能用「實際優先」搶走；判斷依據是權利當時是否已成立，而非哪個請求名稱聽起來更高優先。

若 A、B 的請求只是落在同一 Tick，但實際先後不同，現有 08 的文字仍保留範圍疑義。除非情境已明定兩者屬同一輪競爭或 A 已在之前有效持權，否則不能直接推出 B 贏或 A 贏。

### 4.3 主角介入與確認保護

主角不參加員工預先權排序，可在實際工作尚未被取得時，依其能力、位置、前置與資源提出請求。若主角取得一個員工原本只持預先權的工作，該員工的實際競爭失敗，重新排程；正在包裝則結束包裝，已完成成果保留。

若員工已在操作確認，即使尚未正式動作，主角也不可取代。員工若依 08 合法取消確認，實際執行權立即釋放，需求保留，其他合格角色可重新申請；不能據此推定取消者舊有預先權自動恢復，也不能強制召回已轉做其他工作的員工。預先權是否恢復、如何再次申請仍需確認。

## 五、等待、失敗、逾時與重新排程

### 5.1 等待的原因決定後續

持有效預先權且前置未完成時，原則等待，不轉找其他工作。設備暫時占用則是資源等待，不等於其他人贏得這份菜的階段權利。正在包裝時，資源占用可觸發較高優先且可執行工作檢查；符合時可結束包裝轉做，否則等待，主要規則見 11-03 第三章。

例如另一人正用烹飪台做乙菜，並不能據此說 A 已輸掉甲菜的烹飪權。反過來，若 B 已有甲菜烹飪有效預先權，也不能把 A 無法接手寫成單純等待設備即可解除。前者等資源條件，後者涉及目標階段的權利勝負。

包裝外的持權者在前置完成後遇設備等待，其放棄／轉找行為與期限適用範圍還未完整規定；不能直接套用包裝例外給所有員工。

### 5.2 兩種競爭失敗

預先權競爭失敗，表示員工未贏得當前目標階段；持階段權利但實際競爭失敗，表示原本的機會未轉成實際工作，例如主角合法介入。兩者都使員工放棄該目標，回到授權範圍重新找工作；若包裝正在進行，則結束包裝。

若失敗在員工尚在執行目前底層動作期間已被判定，該動作仍須依一般規則完成，不能因後續目標失敗而回滾或半途消失。何時顯示包裝結束、何時清理殘留權利與開始下一選擇仍需配合 U11-04／05 規格化。

重新排程會重新檢查當下授權、優先度、偏好與工作狀態，不保證立即有替代工作；全部不可執行時等待。競爭失敗不是刪除餐廳需求，也不是讓贏家或其他角色重開已完成工作。允許的送餐交接成功則不歸入失敗，依 11-03 的協作策略處理。

### 5.3 等待期限：方向與候選分開

為避免無限占有，現階段方向是逾時釋放預先權並重新排程。候選模型保留：

`T_limit = α × 前置工作預估剩餘時間 + T_buffer`

這不是已核定的時間公式。α、緩衝數值與平衡交 12；計時起點、是否重新估計、估計變動如何更新期限，以及設備等待是否使用同一期限尚未定。

依 08，全世界管理暫停時工作與計時事件停止，不能在暫停中讓權利因真實時間流逝而偷偷到期；背景及跳時仍須保留同樣的時間成本與事件規則。候選期限如何落到共同世界時間、暫停恢復與跳時跨期限的精確裁決仍需補齊。逾時與前置完成同刻時先釋權或先允許取得，以及對包裝和其他持權的清理順序均未定。

## 六、代表時序：同一道菜由兩人接力

**起始條件：** 甲菜已存在；A 的「取放食材→烹飪→送餐」包裝已因首項階段權利成功取得而啟動。B 有甲菜烹飪資格、啟用該項預先權且已選中此目標。本例無主角、逾時、人工修改與設備阻塞；所有「開始」均已越過相應界線。

1. A 正式取料，該工作已有實際執行權保護，取料預先權按開始後釋放原則退出。B 不能重做取料。甲菜烹飪預先權此時已開放。
2. 本例給定 B 是該輪烹飪預先權唯一申請者，B 成功持權並等待。若 A 也同輪申請，必須補員工排序才能定誰勝出，不能仍寫成 B 必贏。
3. A 完成取料，備料成果留下，甲菜前置條件更新。B 尚未正式烹飪；訂單板應將取料顯示完成，而非把 A 的進度挪成 B 已有烹飪進度。
4. A 要延續包裝時發現 B 的有效權利，不能取得烹飪階段；依競爭失敗結束包裝並重新找工作。B 的權利不是被 A 的包裝優先度壓過。
5. B 在到點及其他實際條件成立後取得烹飪執行權、確認、正式製作。預先權釋放後，實際工作仍受保護。甲菜烹飪完成，但送餐者尚須按自己的權利與策略判斷。

**結果：** A、B 實質合作完成前兩段，A 的包裝未完整完成，成果卻沒有回滾。這是總覽案例 B 的競爭部分；無法從本例推定 B 也必然送餐。

## 七、資訊、未決邊界與交接程度

玩家應能辨識持權者與實際執行者、目標階段、前置等待與資源等待、競爭結果及下一步狀態。資訊可由排程板、訂單板與角色／設施回饋共同承接，具體位置交 13；只顯示「工作中」不足以解釋上述差異。

| 缺口 | 無法唯一推導的結果 | 來源／協調 |
|---|---|---|
| 「開始」相對於取得執行權、確認與正式執行 | 下一階段何時開放、何時釋放預先權、首項如何啟動包裝 | 交接包與 08-01，U11-04 |
| 同 Tick 範圍及完成／取消／逾時先後 | 同刻競爭誰可進入、誰已具有既得權 | 08-01 第五六章，U11-05 |
| 提前申請位置、持權數量與清理 | 員工如何移動、是否可另持權、失敗後殘留狀態 | 08-03／11，U11-04／06 |
| 前置等待與資源等待的交集、非包裝持權等待 | 是否可轉找、期限是否繼續適用 | 11-02／03／04，U11-08 |
| 逾時模型的計時及刷新 | 何時算失效、跳時後哪人先取得 | 08／11／12 |
| 營養不足、睡眠、關店、撤權與恢復 | 進行中工作及預先權是否延續、如何安全釋放 | 08／09／11，U11-06 |
| 後續階段擴展與送餐交接 | 哪個事件開放收洗權、交接成功何時結束包裝 | 11-01／03 |

第二至五章的已確認條文可交接為權利區分、不可重複取得與主要競爭分支的需求；第三章時間表及第六章可供條件式驗收情境。尚不能交付完整同刻裁決、期限與取消恢復演算法。案例 C／D／E／F 的跨機制推演見總覽第十章，均非實測通過紀錄。

依據：交接包決策摘要第 5～7 節、案例 B～F 與待確認清單；[08-01](08-01_世界時間與事件規則.md) 共通執行權。原先製菜權不含送餐，與通用預先權可擴展送餐兩項來源均保留，不能混寫。
