# 14｜遊戲流程測試與調整紀錄

**文件狀態：待驗證計畫與空白紀錄｜遊玩、數值及原型測試尚未執行**

共同政策依 [06](06_遊戲細部設計指引.md)，方法依 [06-01](06-01_初始設計規劃指引.md) 與 [06-02](06-02_正式設計文件規範.md)。本文件持續追加實際紀錄，不建立固定最終版，也不把計畫寫成結果。

## 一、測試目標與責任

透過遊玩、紙上模擬、數值試算或原型驗證，持續檢查設計是否符合 `05` 的遊戲核心與規模目標。

著重遊玩體驗、經濟節奏及設計調整；`24` 著重功能、整合、效能與課程技術驗證，兩者可引用而不取代。

## 二、既有基礎、假設與前置條件

- 以 `01～06` 為依據，`05` 的成長與規模僅作暫定目標；低生存門檻、顧客離開僅損失交易機會及客源研究邊界依 `06`。
- 約 30／90／180 分鐘、約三位員工全流程自動化、第一位員工約 20 份訂單等值成果均待驗證，不是通過結果或固定門檻。
- `07～13` 提供對應玩法與規則，`08～11` 先具備工作、時間、營養、供應與收入概念後，`12` 才能提供可測數值；可先測具備條件的範圍，不必按文件編號等待。
- 目前僅有驗證計畫，尚無遊玩、試算或原型測試的實測數據及通過結果；執行前須補齊必要的玩法規則與數值條件。

## 三、需要設計的紀錄與比較方法

- 遊戲流程測試與紀錄方式。
- 測試版本、條件及結果的追蹤方式。
- 設計修改前後的比較方式。
- 測試發現問題後的調整與回寫流程。

## 四、既有驗證方向需要細化的項目

- 基本生活與第一次員工的體驗測試。
- 新菜單與工作配置變化的測試。
- 全流程及 24 小時自動化的驗證。
- 正常遊玩時間與數值成長的驗證。
- 長期自由經營、生活內容及恢復能力的驗證。

## 五、關鍵待答問題

- 玩家是否能感受到重要升級及新能力的價值？
- 管理問題是否來自合理的遊戲條件，而不是人為製造的障礙？
- 是否存在過度重複操作、長時間等待或缺乏遊玩內容的情況？
- 正常遊玩時間是否符合成長指標？
- 自動化及升級完成後，是否仍具備持續遊玩的吸引力？

| 顧客久候離開 | 只損失該交易機會，無額外聲望、罰款或永久客源懲罰；與新增評論、衛生影響分開觀察，收洗仍由自然用餐因果產生 | `11` 顧客／工作行為、`12` 收支、`13` 回饋 |
| 營養與生活便利性 | 工作中斷、飲食與休息負擔、推薦能否支持實際料理、自動化後仍有生活價值 | `09` 完整規則、`11` 員工、`12` 消耗、`13` 操作 |
| 經營收支 | 合理一般經營、嚴重錯誤配置、無效大量進貨及浪費的差異；不保證任意操作都獲利 | `10` 供應成本、`11` 收入工作、`12` 經濟模型 |
| 失敗與恢復 | 無法補貨／工作時仍可回家、取得有限援助、做基礎料理及手動恢復；援助防濫用 | `08～12` 的移動、營養、援助、工作與平衡 |
| 約 30／90／180 分鐘能力目標 | 正常玩家與進階玩家的成長差異；包含操作、觀察、配置、查閱與思考，不強迫固定路線 | `12` 成長與數值模型、`13` 操作，先具備 `08～11` |
| 效率與跳時 | 指標可解釋配置差異；場景外、跳時與跨日的工作、庫存、人力、事件推進是否合理 | `08`、`11`、`12` 共同規則，不以單一效率乘時間代替全部結算 |
| 長期與後期可玩性 | 自動化、升級後仍有生活、探索及自願最佳化價值，無過度重複、空等或人為障礙 | `09～13` 的完整流程與成長方案 |

## 七、依賴、調整與回寫

可從早期設計開始建立測試紀錄，並在玩法與數值逐步完成後擴充測試範圍。

本文件記錄實際結果、修改原因及驗證結論；確認採用的規則應回寫對應的細部設計文件。

測試前先記錄版本、條件與假設；測試後保留原始結果與證據，區分觀察、推論及調整建議。跨文件修改依 `06` 協調，採用規則回寫主要領域文件，再記錄後續驗證，不以本文件重新定義全部玩法。

補貨差異、營養工作限制、角色數量計數與課程功能整合等現有問題引用 `06` 第九章；未協調前不以測試假設冒充正式決策。
