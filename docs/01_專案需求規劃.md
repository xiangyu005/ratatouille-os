## 1. 專案定位與目標

本專案以餐飲經營模擬遊戲整合餐飲知識庫、OS 演算法、AI Agent、Skill、MCP 及地端／雲端 AI，完成符合課程要求、可操作並可驗證結果的系統。

遊戲採開放式生活與餐廳經營方向，涵蓋家庭、餐廳、地圖及商店，透過營養、採購、料理、員工、升級與自動化形成資源管理情境。正式名稱為「鼠於我的小餐館」，專案資料夾名稱為 `ratatouille-os`；故事、角色、美術及世界觀採團隊原創，具體設定仍待設計。

- 此文件將課程要求以 SYS 編號、已確認遊戲需求以 GAME 編號、未確認提議以 PROP 編號記錄。
- 遊戲與知識庫需整合；玩家的管理策略與 Agent 的系統資源分派分開設計。
- 先確定架構與機制，再進行技術選型；美術參照概念圖，正式套用前需規格化。

本文件記錄功能與限制；遊戲流程見[主要遊戲流程](02_主要遊戲流程.md)，演算法候選見[映射文件](03_專案功能與OS演算法映射.md)。

## 2. 課程要求

### 2.1 知識庫、演算法與 AI

| 編號   | 需求           | 內容與確認重點                                                                              |
| ------ | -------------- | ------------------------------------------------------------------------------------------- |
| SYS-01 | 指定主題知識庫 | 餐飲主題包含食譜、食材、餐廳評論及食品安全規定；具備收集、整理、查詢與維護能力              |
| SYS-02 | 知識庫資料處理 | 資料匯入、清理、切片、去重、來源記錄及維護                                                  |
| SYS-03 | 知識查詢與問答 | 提供查詢或 AI 問答，顯示來源，查無資料時不得編造                                            |
| SYS-04 | OS 演算法整合  | 至少 12 個課堂演算法；各自具有明確用途、輸入、執行結果、Skill 對應及驗證方式；採用清單未定  |
| SYS-05 | Skill 系統     | 至少 25 個可執行 Skill；各有 SKILL.md、名稱、描述、用途、輸入輸出、限制、執行步驟及小型程式 |
| SYS-06 | MCP 整合       | Agent 經 MCP 呼叫 Skill，須能證明工具實際執行                                               |
| SYS-07 | 雙環境 AI      | 同時具備地端與雲端 AI，不能只做其中一種                                                     |
| SYS-08 | AI 工作分派    | 依 CPU、GPU、記憶體、I/O、任務優先權及排程規則決定執行位置，留下理由與執行紀錄              |

Skill 與演算法分開計數，不要求每個遊戲功能都對應演算法，也不要求一個 Skill 對應一個玩法。

### 2.2 網站與結果展示

**SYS-09｜至少 9 個可操作網頁。** 每頁需有實際用途與操作功能。

| 分類   | 頁面用途               | 主要內容                                  |
| ------ | ---------------------- | ----------------------------------------- |
| 共同 1 | 搜尋與問答             | 知識查詢、來源引用、無資料回應            |
| 共同 2 | 資料來源與內容         | 來源、授權、更新時間及內容檢視            |
| 共同 3 | 資料匯入與整理         | 上傳或取得資料、清理、切片、去重、進度    |
| 共同 4 | 維運與評估             | 新鮮度、版本、檢索命中率、錯誤案例        |
| 本課 1 | 任務排程與資源         | 佇列、優先權、等待時間、資源用量、AI 分派 |
| 本課 2 | 快取與記憶體           | 快取內容、命中率、置換結果                |
| 本課 3 | 檔案與權限             | 儲存、讀取順序、存取權限                  |
| 主題 1 | 食材營養比較與替代食材 | 餐飲專屬查詢與比較                        |
| 主題 2 | 食品安全風險與法規速查 | 餐飲風險與法規資料查詢                    |

**SYS-10｜操作與結果展示。** 使用 Skill 或演算法的頁面需包含操作輸入、實際處理步驟、執行結果及統計圖。

### 2.3 架構、資料與交付

| 編號   | 需求        | 內容                                                                                |
| ------ | ----------- | ----------------------------------------------------------------------------------- |
| SYS-11 | 四層架構    | UI 使用者介面、WS 業務及演算法邏輯、DB 資料與紀錄、AI 模型及 Agent／Skill／MCP 協作 |
| SYS-12 | 資料與授權  | 公開或自編資料，不使用真實客戶或敏感個資；保留來源、版本及授權資訊                  |
| SYS-13 | 需求分析 RA | 角色、使用者故事、驗收條件、網頁選單、畫面規劃及業務流程                            |
| SYS-14 | 系統分析 SA | 架構、演算法與 Skill 協作、API、ERD、循序圖、整合與驗證計畫、分工                   |
| SYS-15 | 測試與驗證  | 演算法與 Skill 對答案、可重現測資與證據、地端／雲端執行比較                         |
| SYS-16 | 成果報告    | 現場網站操作、至少 25 頁投影片、AI 提問五題及檢查修正紀錄                           |

SYS-12 的套件與模型限制原為 MIT 授權、非中國來源，一般依賴有例外；此限制已由老師於課堂取消（依專案負責人 2026-10-31 指示），不再作為選型限制。公開或自編資料、去識別化及來源／版本紀錄仍須遵守；雲端模型使用前仍依課程要求確認。

## 3. 已確認遊戲需求

| 編號    | 需求                 | 已確認範圍                                                                       |
| ------- | -------------------- | -------------------------------------------------------------------------------- |

| GAME-16 | 食譜知識庫           | 提供料理、所需食材與製作資訊                                                     |

| GAME-19 | 餐廳補貨             | 補貨區設定後，每日遊戲時間 8:00 自動配送到店並扣款                               |

### 5.2 課程與遊戲範圍差異

目前暫定只經營一間餐廳。餐廳評論納入客源演算法的隱性計算，不另建評論玩法；食安遊戲機制在食材期限之外，增加餐廳環境衛生對客源的影響。遊戲機制不表示已完成課程知識庫、資料來源或九頁功能的整合。

| 差異                    | 後續需決定                         |
| ----------------------- | ---------------------------------- |
| 評論已納入隱性客源運算，不建獨立評論玩法 | 評論數值來源、形成與更新，以及與課程評論知識庫的關係 |
| 遊戲涵蓋食材期限與環境衛生 | 衛生與離店規則，以及食品安全資料、法規速查的整合用途 |
| 遊戲場景與指定九頁不同  | 整合方式及各頁實際操作             |
| 演算法及 Skill 尚未選定 | 使用模型、正式清單及驗證方式       |

### 5.3 長期規劃與目前範圍

AI 動態成就系統列為長期規劃：未來研究由 AI 依遊玩中有趣情況自動頒發獎項。現階段優先完成必要功能，此系統不影響目前設計與分工，待其他功能成熟後再研究，不保證本次專題完成，模型與生成規則尚未指定。

若未完成動態成就，後期以完成所有既定升級、持續經營及挑戰長期客源與經營能力作為目標方向；不把候選升級全部升格為必做內容，也不新增固定結束天數或強制通關。

### 5.4 原創與彩蛋的待處理事項

料理鼠王元素僅保留彩蛋致敬方向，內容與呈現尚未定。著作權與授權事項仍待確認，應配合彩蛋內容及對外展示方式進一步處理。
