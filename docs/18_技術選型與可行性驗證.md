## 2. 鎖定策略

### 2.1 Python

- `.python-version` 固定 `3.14.10`，讓 uv 在專案目錄自動選到這個版本。
- `pyproject.toml` 的 `requires-python` 設為 `>=3.14.10,<3.15`；不允許 3.13 以下，避免團隊成員用到不同 major。
- `uv.lock` 鎖定實際套件版本；安裝指令一律用 `uv sync --locked`，不用 `pip install` 直接改環境。
- 若 AI 套件在 3.14.10 真的沒有 wheel，AI 服務可獨立使用 3.13；這是「服務級例外」，不是改 CORE。詳見 5.2。

### 2.2 Node.js

- `.node-version` 固定 `24.17.0`；`frontend/package.json` 建立後加 `"engines": {"node": ">=24 <25"}`。
- 套件用 `package-lock.json` 鎖定；不用 `^` 浮動版本直接進 main。
- CI／隊員機器以 `node --version` 檢查 24.x；不是 24 就依 `.node-version` 安裝。
- 目前 Node 24.17.0、npm 11.6.2 已在本機可用；FE 尚未建立，所以 build 尚未驗證。

### 2.3 其他

- 資料庫路徑、port、CORS 由 `.env`／環境變數控制，預設值寫在 `.env.example`。
- 金鑰、模型權杖不進 git；log 需遮罩。
- 版本變更需同步 `uv.lock`／`package-lock.json`，並在 `24` 記錄測試結果。

## 4. Node.js 24 評估

### 4.1 結論

**Node 24 沒問題，可以鎖。** 它是 LTS 線，官方維護至 2028 年 4 月；目前機器是 24.17.0。對這個專案的 React／Vite 前端來說，Node 24 在支援範圍內，且比 Node 25（Current，非 LTS）更適合課程專案。

| 候選 | 狀態 | 判斷 |
|---|---|---|
| Node 22 | LTS，較舊 | 可用，但沒必要降 |
| **Node 24** | **LTS，維護至 2028-04** | **採用** |
| Node 25 | Current，非 LTS | 不適合當專案 baseline |
| Node 26 | 新 Current | 太新，套件與隊員環境風險較高 |

### 4.2 鎖定方式

1. `.node-version` 寫 `24.17.0`，讓 nvm／fnm／Volta 等工具選到同一版。
2. `frontend/package.json` 建好後加：
   ```json
   "engines": { "node": ">=24 <25" }
   ```
3. 用 npm 11（Node 24 內建）與 `package-lock.json`；不用 `npm install` 產生的浮動版本直接進 main。
4. CI／報告前跑 `node --version`，確認 24.x。

### 4.3 npm 還是 pnpm？

**先選 npm。** 理由：

- Node 24 已內建 npm 11，隊員不用另外裝套件管理器。
- 本專案目前只有一個 `frontend/`，沒有 monorepo／workspace 需求；pnpm 的優勢暫時用不到。
- npm 的 `package-lock.json` 對課程展示與 CI 已足夠。
- pnpm 10.34.5 仍可用；若未來真的拆多個前端 package，再評估遷移。

### 4.4 尚未驗證

- 還沒有 `frontend/`，所以 `npm create vite`、`npm run build`、dev server、CORS、WebSocket 連線都還沒跑。
- React 19.3.1／Vite 8.3.5／TS 7.0.2 已選定；仍待 scaffold 驗證。

## 6. 分項選型

### 6.1 Web／API：FastAPI + Uvicorn + Pydantic

**選定：** FastAPI 0.162.0、Uvicorn 0.54.0、Pydantic 2.14.2。

**理由：**

- Pydantic 直接產生 OpenAPI，FE／AI 可共享契約。
- WebSocket 與 REST 同一個 app，符合 snapshot + incremental events。
- 非同步足以支撐單機 20 Tick/s 的 CORE。

**替代方案：**

| 候選 | 不採用原因 |
|---|---|
| Flask | 契約、WS、型別要自行拼 |
| Django | 對本專案過重 |
| NiceGUI | 全 Python 方便，但終端 UI 控制力與 FE／CORE 分層不符 |

**已驗證：** `/health`、`/api/v1/*`、`/ws/events`、Pydantic 422、TestClient WS。

**待處理：** FastAPI TestClient 對 `httpx` 的 deprecation warning；之後可換 `httpx2`，目前不影響。

### 6.2 資料庫：SQLite + WAL

**選定：** SQLite 3.53.1（Python 標準庫），WAL 模式；**CORE 與 AI 分庫**：

- `data/core/core.sqlite`：遊戲世界、event log、snapshot、idempotency（CORE 擁有）。
- `data/ai/rag.sqlite`：documents、chunks、citations、ingest、agent／model／tool 紀錄（AI 擁有）。
- 不共用 DB、不跨庫 JOIN；AI 只把 CORE 識別碼當 opaque reference。細節見 `20`。

**理由：**

- 單機課程專案，不需要 PostgreSQL 的維運成本。
- 交易可同時寫 event、snapshot、idempotency。
- 與 CORE 的單一寫入者模型一致。

**替代方案：** PostgreSQL（過重）、DuckDB（分析型，非 OLTP）、JSON 檔（無交易）。

**已驗證：** WAL、command commit、snapshot reload、idempotency、determinism。

**限制：** 單寫入者；不適合多機或網路磁碟。未來真需要多人併發再評估 PostgreSQL。

**替代方案：** NiceGUI／Dash（全 Python，但版面控制與分層不符）、Svelte（備選）、Godot／Unity（否決，不是完整遊戲引擎需求）。

**待實作驗證：** `npm create vite`、build、dev server、CORS、WS、9 頁 shell、Chart.js。

**版本策略：** React／Vite 版本已選定，scaffold 時以 `npm install` 結果 pin；Node 24.17.0。

### 6.5 Numba

**選定：** Numba 0.68.x，只用在 profiler 證實的 CPU hotspot。

**適合：** batch simulation、time skip、queue／resource allocation、scheduler benchmark、Monte Carlo、cache simulation。

**不適合：** FastAPI、JSON、DB、LLM、MCP、複雜 object graph。

**規則：**

1. 先有 reference 實作與固定測資。
2. 再加 `@njit(cache=True)` 版本。
3. 測試必須證明 reference 與 optimized 結果一致（或明確定義容差）。
4. Numba 不可用時 fallback 到 reference。

**現況：** AI venv 已安裝 0.68.1，`@njit(cache=True)` smoke 通過；CORE 尚未接入 optimized kernel。

### 6.6 測試：pytest + httpx

**選定：** pytest 9.2.0、httpx 0.28.1。

**已驗證：** 25 tests，涵蓋排程、command／event、idempotency、determinism、snapshot reload、REST、WS、architecture invariants。

**待補：**

- `pytest-asyncio`／`anyio`：目前 async 測試用 `asyncio.run`，數量變多再改。
- OpenAPI → TS types 的 contract test。
- Playwright E2E（FE 建立後）。
