# 24｜系統測試與品質驗證紀錄

**狀態：持續累積｜量測範圍為 CORE 服務層，非遊戲玩法驗證**

本文件記錄已實際執行的功能、整合與效能測試；遊玩體驗與設計調整記入 [14](14_遊戲流程測試與調整紀錄.md)。未測項目不得視為通過。

## 一、CORE 指令延遲（2026-11-02）

### 1.1 背景

[17](17_系統架構與模組設計.md) §11.4 要求 CORE 的 tick 預算固定（每 tick < 5 ms，依硬體調整），超過須記錄。開發中發現指令延遲明顯超出預算，因此先量測再優化。

量測前觀察：`POST /api/v1/commands` 暖機後 p50 約 11.5 ms、尾端 16.4 ms，同一個世界狀態的 `GET /api/v1/snapshot` 只要 1.9 ms，顯示成本集中在寫入路徑而非 HTTP、JSON 或序列化。Numba 不在此路徑上（17 亦規定 API／DB／JSON 不進 Numba），因此延遲與 JIT 無關。

### 1.2 量測方法

- 單機、單一 uvicorn worker、httpx keep-alive 連線；暖機 5 次後取 35 次樣本。
- 指令內容為 `ENQUEUE_TASK`，每次帶新的 idempotency key。
- 另以 in-process 拆解 `WorldEngine.execute` 各階段與 SQLite 單獨操作，確認成本歸屬。

### 1.3 結果

| 項目 | 優化前 | 優化後 |
|---|---|---|
| `POST /commands` p50 | 11.54 ms | **2.23 ms** |
| `POST /commands` p90 | 13.86 ms | 2.51 ms |
| `POST /commands` max | 16.40 ms | 3.65 ms |
| `GET /snapshot` | 1.91 ms | 2.34 ms |
| `POST /save` | 未提供 | 2.81 ms |
| `POST /load` | 未提供 | 2.28 ms |

SQLite 單項成本（同一顆 `core.sqlite`）：

| 動作 | 成本 |
|---|---|
| 開新連線 + `PRAGMA journal_mode=WAL` + 關閉 | 1.46 ms |
| 新連線上執行 1 筆 INSERT（含 commit） | 4.21 ms |
| **同一條長連線**上執行 1 筆 INSERT | **0.045 ms** |

### 1.4 判讀與調整

- 主因是每個指令開兩條新 SQLite 連線（idempotency 讀取 + commit），每條都重跑 PRAGMA；關閉最後一條連線時 WAL 被 checkpoint 掉，下一個指令再重建。與磁碟 fsync 無關（`synchronous=OFF` 僅由 0.045 ms 降至 0.036 ms）。
- 調整為單一釘住連線、PRAGMA 只設定一次，並以執行緒鎖保護（FastAPI 的同步路由在 threadpool 執行）。調整後 p50 2.23 ms，符合 17 的 5 ms 預算。
- 尚未驗證：多 worker、並行寫入、世界狀態放大到數千任務後的成本。目前每個指令仍寫入整份世界 snapshot（7.2 KB），此寫入量隨狀態大小線性成長，須另行量測再決定是否改為週期性快照。

## 二、驗收項目

| 項目 | 結果 | 備註 |
|---|---|---|
| 指令與事件寫入一致（單一交易） | 通過 | pytest |
| idempotency 重送回傳快取結果 | 通過 | pytest |
| 存檔、讀檔、checksum 驗證 | 通過 | pytest；損毀存檔回 409 `SAVE_CORRUPTED` |
| 讀檔後 WS 客戶端重新同步 | 通過 | pytest；`SNAPSHOT` 帶 `reason=save_loaded` |
| `snapshot?since_event_id=` 增量 | 通過 | pytest |
| 事件依 type／sim_time 篩選 | 通過 | pytest |
| 所有 response 帶 `request_id` | 通過 | pytest；與 `x-request-id` header 一致 |

## 三、待驗證

- 多 worker／多程序同時寫入同一顆 `core.sqlite` 的行為。
- 世界狀態規模化後的指令延遲與 snapshot 寫入量。
- 長期執行下的 WAL 成長與 checkpoint 行為。
- AI 服務與 CORE 的整合延遲（本紀錄只涵蓋 CORE）。
