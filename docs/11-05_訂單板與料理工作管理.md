# 11-05｜訂單板與料理工作管理

**狀態：遊戲設計規格稿｜監控語意與一般改排行為可供分段交接；多重修改、持權與確認期生效細則仍待確認，未經模擬驗證**

[返回 11 總覽](11_餐廳經營系統.md)。訂單板負責料理工作資訊與人工調整，範圍從取料到送餐；員工整體職責由排程板設定，工作由員工自主選擇與競爭。

## 一、玩家如何查看與介入

玩家打開訂單板，看到廚房有哪些菜品待做、主角與員工目前正在處理哪份菜、該菜進到哪個階段與工作進度。玩家可能發現甲菜已完成取料，但烹飪尚未開始；這時應能辨識是還沒人取得、有人持預先權等前置／資源，或已有人取得實際執行權正在確認，而不是一律顯示「尚未製作」。

玩家可以調整待做菜品順序，影響後續選擇具體菜品的依據；也可以修改某員工下一份要處理的菜品／工作。這兩種操作都不代表立即取得目標工作。正在正式執行的底層動作保持進度，修改到下一工作邊界才生效，新目標仍需符合資格、前置、資源及權利條件。

例如 A 正在取放甲菜食材，玩家指定 A 下一份改處理乙菜。本輪能確定 A 不會因操作立即丟掉現在的進度，甲菜已完成成果會留下；若改動影響甲菜包裝，包裝在安全邊界結束。乙菜若屆時已由 B 取得，A 不能拿人工修改當成優先奪取權。

## 二、資訊範圍與顯示語意

### 2.1 料理需求、角色及權利應分開理解

| 要辨識的資訊 | 對玩家的意義 | 不可誤呈現為 |
|---|---|---|
| 待做菜品及順序 | 廚房尚需處理的具體菜品與排序依據 | 整份菜已指派給特定員工 |
| 菜品必要階段 | 取料、烹飪、送餐中哪些已完成、哪些尚需處理 | 某一員工擁有整道菜的所有階段 |
| 實際執行者與目前動作 | 競爭確定後，誰取得該工作、正處於確認或正式執行 | 只是選中目標或開啟預先權開關的人已開工 |
| 目前工作進度 | 該底層動作已執行多少、是否完成 | 等待或預先權持有時間就是料理製作進度 |
| 等待與受阻原因 | 前置未完成、資源占用、尚未取得等差異 | 所有等待都是競爭失敗 |
| 包裝與下一安排 | 角色正延續哪份菜，人工變更會作用於哪個後續目標 | 修改下一安排即取消現在動作 |

實際工作競爭確定後，訂單板才把角色顯示為該工作執行者。若需顯示持預先權者或選中目標者，必須清楚區分為提前權利或意圖；是否直接放在主板、詳細資訊或其他既有回饋位置交 13 決定，不在本檔新增畫面。

同一道菜的取料可能由 A 完成、烹飪由 B 正在做，板上應呈現這些不同事實。不能因烹飪者換成 B 就重置取料成果，也不能把 A 的包裝失敗當成菜品失敗或整單取消。個別階段進度如何呈現為整體進度、是否保存操作歷史仍未定，本文不要求新增歷史紀錄玩法。

### 2.2 板外資訊與監控時效

接待、進貨、收盤及洗碗不在本板管理範圍，但仍應透過場景或其他介面讓玩家觀察；本板不替全店分派職責。員工有沒有資格接待、每種工作優先度與預先權開關，主要由 11-02 的排程板設定。

「即時顯示」表示反映當下世界狀態，不要求在全域暫停中繼續推進工作。管理與配置時全世界暫停，恢復後繼續原進度；只開板觀察是否也暫停仍須 08／13 確認。主角離場或跳時後，資料須反映當下實際結果，不能把離場前的未來預測當成已完成事實。

## 三、菜品排序如何影響工作

玩家可調整廚房待做菜品的順序。這是對後續具體菜品選擇的輸入，不是立即把最高一份交給第一名員工。員工仍先依資格與工作優先度挑工作種類／包裝，再依製菜偏好或菜品順序挑目標；不在授權範圍、前置或權利不符合的目標，不因移到前面而立即可做。

例如 A 正在做甲菜，玩家把乙菜移到甲菜前面，A 的目前底層動作不會停止，甲菜已完成階段也不會倒退。若另一名空閒員工 B 以訂單板順序作為選菜依據，且本例乙菜是其最高合格候選、沒有衝突偏好，B 可選乙菜再參與競爭；排序本身沒有先替 B 拿到執行權。

當員工製菜偏好與板上順序衝突，或重新排序影響已啟動包裝鎖定菜品時，現有規則沒有完整說明如何判斷影響。不能一律說全局重排會結束所有包裝，也不能一律保證完全不影響；只有「人工變更影響其鎖定安排時，下一邊界結束」的原則已確認。

## 四、修改某員工下一工作

### 4.1 從操作到實際取得

1. 玩家查看員工目前菜品、底層動作、進度及包裝狀態，決定修改其下一份菜品／工作。這是修改後續目標，不是修改已完成成果。
2. 進入管理操作後全世界暫停，工作進度保留。玩家改好目標時，需能辨識這是下一安排，而非已接管成功；實際按鍵、送出方式與版面由 13 定義。
3. 恢復世界後，正在正式執行的底層動作仍按原工作前提推進。不能在管理操作中或恢復瞬間將它結算、退回或切成新目標。
4. 到下一工作邊界，修改才對後續安排生效。若它影響員工包裝鎖定的菜品，原包裝在該安全邊界結束，已完成成果留下。
5. 員工檢查新目標當時的資格、前置、資源及權利。若能取得，經正常實際工作生命週期執行；若已被別人取得或完成，回到正常競爭／尋找工作，不強制回收別人的成果。

「下一工作邊界」對一般已正式執行的情況，可確定不早於目前底層工作完成；但取放與收洗的底層粒度未定，不能直接宣稱整道菜做完才生效。操作確認中、僅持預先權等待中或原本空閒時收到修改，確切生效點仍須補規格。

### 4.2 修改不創造額外權利

人工指定不讓員工跨越原有工作／菜色資格，不自動開啟未到時機的預先權，也不能越過另一員工有效預先權或已取得的實際執行權。它設定下一目標，並未保證目標一直保留到該員工抵達。

員工若因新目標不可取得而重新排程，仍只找已授權工作；無可執行候選則等待。新目標缺料、前置未完成或設備占用時，要依其是否持權、是否仍有包裝及等待原因處理，不可把「修改沒立刻執行」一律說成競爭失敗。

修改造成原包裝結束，不代表成品自動送到交接桌、下一員工自動接手或其餘預先權立即全部清除。成品位置由 11-01／03 的具體工作銜接決定，權利清理由 11-04 與本檔共同待補，不能用板上一次操作代替未定的世界動作。

## 五、完整推演：甲菜工作中改做乙菜

**起始條件：** A 正式執行甲菜取放工作，甲菜包裝已啟動；本例將當前取放作為已辨識的底層工作，不替所有食譜核定粒度。B 空閒，具有乙菜烹飪資格。乙菜已備料、所需設備可用，尚無有效預先權或實際執行者。A 也具備乙菜烹飪資格。本例不涉及營養、逾時或主角工作介入。

1. 板上顯示 A 正在取放甲菜；乙菜待烹飪，尚未顯示誰正在執行。A 的包裝狀態與乙菜無關。
2. 玩家進入管理，世界暫停，指定 A 下一份改為乙菜烹飪。此時 B 也不會在玩家思考期間偷偷開工，A 的甲菜進度維持。
3. 恢復後，A 繼續甲菜目前動作。B 依自身配置選乙菜，先在 A 完成之前取得乙菜烹飪執行權並進入確認／正式執行；本例明定這段先後，避開同刻疑義。
4. A 完成甲菜取放，備料成果留下；人工修改影響其鎖定安排，甲菜包裝在安全邊界結束。甲菜烹飪尚未由此自動指派給誰，需後續合法選擇與競爭。
5. A 檢查乙菜時，B 已有實際執行權。A 不能憑人工指定或較高員工順位搶走；回到找工作流程。板上仍顯示 B 的乙菜工作，不能先換成 A 再回復。
6. 若此時 A 沒有其他可做授權工作，A 等待；若有，依 11-02 選擇。甲菜已備料、B 的乙菜進度與資源使用均保留。

**對照分支：** 若 B 沒先取得、乙菜在邊界時仍無有效預先權或其他競爭，且 A 到點、資源等條件均成立，A 才可取得乙菜工作。若只有 B 的有效預先權，也足以限制 A 的一般實際競爭，但與「B 已在確認／執行」屬不同狀態。不能只由「已指定 A」推出其中任一結果。

## 六、資訊回饋、缺口與交接程度

修改後應能辨識目前工作、下一目標、尚待邊界生效及實際取得結果。若最後未取得，原因需與事實相符：目標已被取得、已完成或其他前提不成立，而非籠統顯示所有修改都成功執行。文字與位置交 13，這些是既有行為需要的資訊，不新增工作功能。

| 缺少的規則 | 受影響結果 | 責任 |
|---|---|---|
| 製菜偏好與全局菜品排序的優先關係 | 員工面對不同排序時選哪份菜 | 11-02／05 |
| 重排何時算影響包裝鎖定安排 | 哪些包裝需結束，哪些繼續 | 11-03／05 |
| 確認中、空閒或持預先權等待時的修改生效點 | 是否取消確認、何時換目標與釋權 | 08／11-03／04，U11-04／06 |
| 多次修改與資格撤銷的共同順序 | 以哪份下一安排為準、何時變非法 | 11-02／05，U11-05／06 |
| 改排後成品位置與剩餘權利清理 | 下一角色可在哪裡接手、何時能競爭 | 11-01／03／04 |
| 單純開板觀察的暫停分類 | 顯示與世界進度是否持續更新 | 08／13 |

第二章監控語意、第三章排序的影響範圍、第四章正式動作中的改排路徑與第五章條件式情境，已可交接供介面需求、驗收條件與後續規格制定。表列情況仍不足以直接實作所有輸入組合。總覽案例 G 保留跨機制推演；本輪未執行 UI、遊玩或背景一致性測試。
