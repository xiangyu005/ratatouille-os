# 11-01｜餐廳工作流程與狀態

**狀態：遊戲設計規格稿｜流程與一般工作生命週期可供分段交接；工作粒度、資源時點與例外仍待確認，未經模擬驗證**

[返回 11 總覽](11_餐廳經營系統.md)。本文件負責工作如何產生、需要什麼條件、角色如何執行，以及完成結果如何交給下一階段。員工選哪份工作由 11-02 主導，包裝與權利分別由 11-03／04 主導；本文說明這些機制在實際流程中的行為。

## 一、玩家如何參與一段餐廳工作

以下情境假設餐廳正在營業、有可接待顧客與可用座位，菜品具備製作資格，角色有工作能力。這些是為了推演正常路徑的情境條件，不代表固定初始資源或一客只能點一道菜。

玩家看到櫃台有顧客，先由主角或已授權的員工接待。顧客指定菜色後自行入座，廚房出現待做菜品。玩家可讓主角親自處理，也可觀察員工依排程板選擇工作。此時板上出現菜品只代表工作需求存在，尚不代表有員工取得其全部製作工作。

角色處理取放食材，將餐廳儲藏中的所需食材帶到烹飪桌；備料完成後，符合資格與權利條件的角色才能實際烹飪。烹飪者可能就是取料者，也可能是另一名員工。烹飪完成後，成品依包裝送餐配置直接送出或經送餐桌交接，再由取得送餐工作的角色送至顧客餐桌。未完成烹飪時，下一名角色即使已取得送餐預先權，也不能拿不存在的成品上菜。

顧客用餐後離開，才自然產生收盤／洗碗需求。玩家可從餐盤堆積與員工等待判斷分工是否合適；這些後續工作不在料理訂單板的取料至送餐範圍內。收入由系統計算，但結算發生在服務的哪個時點仍未定，不能在送餐完成時逕行推定已入帳。

當玩家親自操作時，主角需到互動範圍提出實際工作請求；員工則依安排移動到工作定點後提出實際請求。取得執行權後均經過操作確認，才正式執行。移動與確認具有成本，不能將自主員工寫成選中工作後立即產生成果。

## 二、工作需求來自三條相連業務

### 2.1 進貨與料理分流

貨物先抵達進貨區，再由人員放進儲藏庫。料理取用儲藏中的食材，不要求每份菜都先經歷配送。入庫可與其他菜品的料理並行，只要各自的角色、工作與資源條件成立；並行不代表可超出尚未定義的設備容量。

01 GAME-19、02 第 5.3 節及 10 保留每日 8:00 配送扣款需求。配送適用階段、採購決策與資金／容量不足處理仍待協調。對本文件而言，「貨物已到店」與「食材已可從儲藏取用」是兩個應辨識的狀態；精確入帳及可用庫存更新時點尚未定，見總覽 U11-07。

### 2.2 顧客帶來料理與收洗工作

顧客生成後走到櫃台排隊，由主角或員工接待；顧客指定菜色、自行入座，廚房新增待做菜品。顧客可一次來多位，座位有限，藉此限制未完成訂單數量。櫃台久候可離開，只損失當次交易機會；已入座顧客不因料理久候離開。

目前不能唯一推導滿座時是暫停接待、延後點餐或採取其他處理，也未定義座位占用／釋放時點與每筆訂單的菜品數。這些缺口影響新料理需求何時建立，不得用無限候位區或一客一菜補齊。環境衛生造成離店是另一來源，其觸發階段由總覽第八章保留待設計。

收盤與洗碗由實際用餐離開後自然產生。不能在沒有用餐的情況下隨機新增餐盤工作，也不能假定送餐完成就立刻出現洗碗需求。顧客用餐時間、收盤與洗碗的具體拆分、餐桌何時恢復可用，均仍需設計。

### 2.3 料理維持必要先後

同一道菜須按取放食材、烹飪、送餐的必要先後推進。前階段完成結果可以由不同角色接續使用；任一角色選中菜品、取得某階段預先權或啟動包裝，都不代表可跳過必要前置或擁有整道菜。

「取放食材」是目前討論的業務階段名稱，尚未決定取與放是否拆成不同底層工作。「底層工作」指實際取得並執行、一般調度不任意中斷的工作單位；不得因文字把取放合稱，就宣告整段搬運已有完整的不可中斷界線。

## 三、各工作從前提到交接的行為

### 3.1 入庫與接待

入庫需要進貨區已有貨物、角色可執行且儲藏條件允許。角色完成入庫後，食材成為餐廳儲藏流程的一部分，後續取料依當下可用狀態判斷。若沒有到貨，不能僅因員工有入庫資格就產生工作；容量不足時的停留位置、部分入庫與搬運批量尚未定。

接待需要顧客正在等待及角色可執行。完成接待會銜接顧客指定菜色、入座與廚房需求；這些事件間的精確先後和滿座阻擋點尚未定。接待不是每道料理包裝的一部分，也不能和洗碗任意組成一個連續包裝。

### 3.2 取放食材

角色先選定某份待做菜品的取放工作，仍須檢查該菜的製作與供應資格、實際食材、角色能力及工作所需空間。菜單、食材與所需廚具資格必須具備；食材已解鎖不表示庫存足夠，家庭庫存也不能直接當餐廳庫存使用。

符合條件並取得實際執行權後，角色經確認與正式動作，將所需食材放到烹飪桌。成果須可供該菜後續烹飪使用，不能因原員工改做其他工作或包裝結束而消失。移動、取料、放置各自如何拆成底層工作、材料何時預留與扣除仍未定；因此此處不承諾一次取齊、不允許部分取料或取消時全數退回。

### 3.3 烹飪

烹飪需要該菜必要備料完成，角色及所需廚具／設備等實際條件成立。前置取料僅在進行中時，員工可能取得烹飪預先權並等待，但尚不能實際製作。前置完成後也不保證原取料者直接接手：若別人已有有效預先權，原員工須遵守其保護關係。

取得烹飪實際執行權後，角色進入確認，確認完成再正式製作；正式動作一般不中斷。製作完成產生成品，並依所選送餐模式處理。各菜耗時、設備同時服務數量、製作期間是否要求角色持續留在原地，以及設備精確釋放時點仍未定。

### 3.4 送餐與成品交接

送餐是烹飪後的下一個實際工作。只有含連續「烹飪→送餐」的員工原子包裝能設定繞過送餐桌；單獨烹飪或只包到烹飪者完成後須放送餐桌。包裝可採直送、允許提前預選交接否則直送、完成後送餐桌交接三類配置，完整責任由 [11-03](11-03_原子包裝與連續工作.md) 第四章維護。

成品放到送餐桌不表示送餐已完成。接手者仍須取得相應實際工作，符合資源與移動前提，經確認與正式執行後將成品送至餐桌。提前取得送餐預先權，只保障適用範圍內的工作機會，不能使烹飪立即完成，也不等於已拿到成品。

成功交接保留原烹飪成果；接手者不重做取料或烹飪。交接的搬運拆分、成品在交接失敗時的位置、送餐桌容量及原包裝的精確結束點未定。主角手動是否須先放桌與其連續操作方式亦保留 U11-09，不擅設直送例外。

### 3.5 收盤、洗碗與丟棄

用餐後產生收洗需求，流理臺承接已知的清洗用途；「收盤／洗碗」目前不代表已決定兩者是一個不可分動作或兩個可分配動作。未收餐盤與衛生、蒼蠅、離店的關係依總覽第八章，但清洗完成是否立即恢復全部衛生尚無規則。

垃圾桶沿用 GAME-12 的食材丟棄用途。過期食材如何處理、垃圾容量與清運、是否有獨立員工垃圾工作尚未決定，本輪不新增工作種類。

## 四、工作狀態如何改變

### 4.1 必須分開追蹤的狀態

同一時刻應分別追蹤：菜品進到哪個必要階段、角色選了什麼目標、誰持有哪一階段的預先權、誰取得當前實際執行權、資源是否可用，以及包裝是否啟動。這些是遊戲資訊的區分，不是資料表設計。

例如「A 正式取料、B 持烹飪預先權等待」表示取料成果仍未完成、B 尚未開始烹飪；不能簡化成「B 正在做這道菜」，而遮掉 A 的進度。A 的包裝是否延續也必須在下一階段競爭後判定。

### 4.2 一般實際工作生命週期

| 當前狀態 | 事件與必要判斷 | 可確定的變化 |
|---|---|---|
| 有需求、尚未取得 | 主角到互動範圍或員工到工作定點提出實際請求；檢查前置、角色、資源及權利 | 成功者取得該底層工作執行權；未成功不代表需求消失 |
| 操作確認 | 執行權已屬該角色，確認成本尚在進行 | 其他人不可重複取得；主角不能移動，執行者可取消確認 |
| 確認取消 | 取消發生於尚可取消的確認期間 | 立即釋放實際執行權、保留需求；已轉做別項工作的角色不被強制召回 |
| 正式執行 | 確認完成 | 一般排序變動、較高優先工作或人工改下一工作均不搶占目前動作 |
| 完成 | 該底層工作完成 | 更新成果，按具體工作規則釋放執行權與相關資源，再檢查後續前提 |

此處承接 [08-01](08-01_世界時間與事件規則.md) 第三章。取消是否退料、確認期間條件失效與取消／確認完成同刻的先後仍未定。原交接包所稱「開始」與上述取得執行權／正式執行如何對齊，見 U11-04；不因本表存在就自行核定預先權的切換時點。

### 4.3 等待不等於失敗

前置未完成時，不得執行依賴其成果的工作。若員工已有有效預先權，原則等待，不轉找別項；若尚未取得工作，須依其當下選擇／包裝狀態判斷，不能把兩者合併為同一等待。

資源暫時占用時，工作可能仍屬可追求的目標，不能直接寫成競爭失敗。正在包裝的員工可因此檢查有無較高優先且可執行的授權工作；有時可結束包裝轉做，沒有則等待。若是目標階段權利已由別人贏得，則屬競爭失敗，放棄目標並重新排程，進行中的包裝在適用安全邊界結束。詳細區分見 11-03／04。

已完成結果在上述轉換中保留。營養不足、睡眠、關店、資格撤銷與正式執行中離場屬未完成的特殊邊界，不能套一般不中斷規則推定必須做完，也不能反向推定立即停工。

## 五、九類設施及可見互動

| 設施 | 已知互動與玩家可辨識狀態 | 尚缺規格 |
|---|---|---|
| 接待櫃台 | 顧客排隊、角色接待 | 滿座處理、接待動作界線 |
| 進貨區 | 到貨與待入庫工作 | 到貨容量、批量、入帳 |
| 儲藏庫 | 食材持有與取用 | 容量、預留、扣除、保存與搬運 |
| 烹飪桌 | 食材放置與備料成果 | 占用與交接、可同時備幾份菜 |
| 烹飪台 | 烹飪進行、等待或完成 | 與舊「灶台」名稱對照、使用與釋放 |
| 送餐桌 | 成品暫存、等待接手 | 容量、交接失敗與取放粒度 |
| 內用餐桌 | 入座、送餐、用餐與未收盤 | 座位占用／釋放與餐盤限制 |
| 流理臺 | 清洗工作與資源使用 | 收洗拆分、容量與衛生結果 |
| 垃圾桶 | 食材丟棄 | 容量與後續處理是否形成工作 |

九類設施不是九個全數起始提供的物件。01／02 的小冰箱、烹飪台、灶台與本輪烹飪桌／烹飪台用語仍須對照，見 U11-02。固定布局、可通行路徑、互動範圍與員工工作定點依 [08-03](08-03_空間移動與場景互動.md)；角色可互穿不解除設備互斥，玩家也不能據「布局待設計」推定可搬動家具。

## 六、交接範圍、缺口與驗證

本文件第二至四章可供需求與介面設計使用：辨識工作來源、必要先後、角色接力、確認與正式執行、完成結果保留及不同等待原因。具體工作仍不能只憑本檔直接決定耗時、扣料、占用或自動恢復行為。

| 待確認資訊 | 缺少時無法決定的結果 | 責任與關聯 |
|---|---|---|
| 取放、收洗的底層粒度及移動邊界 | 人工修改或包裝結束究竟在哪個動作後生效 | 11／08，U11-04／06 |
| 食材與設備的預留、扣除、釋放 | 取消退料、多人爭用及資源何時可用 | 11／10／08，U11-02／07 |
| 滿座及訂單／座位對應 | 接待是否能繼續、廚房何時新增菜品 | 11，U11-01／03 |
| 完成與交接動作邊界 | 成品位置、送餐桌阻塞、包裝結束後交給誰 | 11-03／04，U11-09 |
| 營養、睡眠、關店及場景交接 | 進行中動作、持權、等待如何接續 | 08／09／11，U11-06 |

後續驗證需檢查三條業務能獨立推進又保持因果、前置未完成不產生成果、接手不重做已完成階段，以及即時／背景／跳時保留相同成本與狀態。目前完成的是文件推演邊界整理，未執行遊玩或模擬測試。
