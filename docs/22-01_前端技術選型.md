## 1. 設計目標

FE 不是遊戲引擎，也不是低密度 SaaS dashboard；它是「高級人類終端機」：

- 高資訊密度、control station／terminal／debugger 風格。
- 9 個課程頁 + `/game` 共用同一個 shell。
- snapshot + incremental events，不每幀重傳整個 world。
- FE 只保存 UI state；世界狀態一律來自 CORE。
- command 送出後等 CORE 驗證與 event，不在前端自行改錢、改員工狀態。

## 3. 為什麼是 React + TypeScript + Vite

- React 19.3 是目前穩定世代；生態、型別、測試工具完整。
- Vite 8 啟動快，適合頻繁調整 inspector／terminal；SPA 不需要 SSR。
- TypeScript 7 strict 可承接 OpenAPI 產生的型別，避免 Python `worker_id` 與 React `id` 各講一套。
- 不用 Next.js：本專案是本機 SPA，沒有 SEO／SSR／server action 需求；多一層 server 只增加複雜度。
- 不用 Vue／Svelte：不是不能做，而是團隊與既有文件都以 React 為基準，沒有換的理由。

## 4. 路由與 9 頁

```text
/                 → redirect /game
/game             → 主要 simulation / terminal
/search           → 搜尋與問答
/sources          → 資料來源與內容
/ingest           → 匯入與整理
/ops              → 維運與評估
/os/tasks         → 任務與資源
/os/cache         → 快取與記憶體
/os/files         → 檔案與權限
/food/nutrition   → 食材營養比較／替代
/food/safety      → 食品安全風險／法規
*                 → 404 terminal page
```

- 9 個課程頁 + `/game`；全部共用 `AppShell`。
- 頁面用 `React.lazy` 分 route chunk；Chart.js 只在有圖表的頁載入。
- 頁名用主題語言，不用演算法名稱（FCFS／LRU 只出現在 process trace 與頁尾「用什麼算」）。
- 每頁（使用 Skill／演算法者）固定四區：操作區 → 過程區 → 結果區 → 統計圖。

## 5. Server state 與 WebSocket

### 5.1 分工

| 狀態 | 存放 | 工具 |
|---|---|---|
| snapshot、tasks、resources、sources、documents、metrics | server cache | TanStack Query |
| WS 連線、last_event_id、event buffer、UI filters／selection | client | Zustand |
| 表單輸入、modal open、command history | client | Zustand／local component state |
| authoritative world | **只在 CORE** | 不進 FE store |

### 5.2 流程

```text
mount
  → GET /api/v1/snapshot（TanStack Query）
  → WS /ws/events
  → event 進 Zustand buffer
  → 若 state_version 變了，debounce invalidate snapshot/tasks/resources
  → UI 重繪

command
  → POST /api/v1/commands（mutation，帶 idempotency_key）
  → 202 accepted
  → 等 WS event 或 refetch
  → 不 optimistic 改 authoritative state
```

- Query keys：`['snapshot']`、`['tasks']`、`['resources']`、`['events', filter]`、`['meta']`。
- WS 重連：exponential backoff；帶 `last_event_id` 補事件；若缺口太大，直接 refetch snapshot。
- 事件 buffer 上限 500；超過丟 oldest，但保留 last_event_id。
- `state_version` 是 FE 判斷是否 stale 的主要依據，不用時間猜。

### 5.3 Command

- FE 產生 `idempotency_key`（crypto.randomUUID）。
- 錯誤依 `error.code` 顯示；不把 Python traceback 丢給使用者。
- 金額／庫存／員工狀態不在 FE 計算；只顯示 CORE 回傳結果。
- 禁用：`money -= 100`、`worker.state = "COOKING"`。

## 6. UI 系統

### 6.1 視覺方向

- 深色 terminal／control station；不是大型圓角卡片。
- 顏色：背景 `#0b0e11`、panel `#11161c`、border `#25303a`、text `#c9d4df`、accent `#4fd1c5`／amber。
- 字體：`ui-monospace, "Cascadia Code", "JetBrains Mono", monospace`；數字用 tabular-nums。
- 12～13px 基礎字級；密集表格、1px 邊框、2px 圓角。
- 動畫只用在狀態變化；支援 `prefers-reduced-motion`。

## 7. 技術細節

### 7.1 API 契約

- CORE 的 OpenAPI 是唯一來源。
- `scripts/generate_types.py` 匯出 `openapi.json`；`npm run gen:api` 產生 `src/api/schema.d.ts`。
- `openapi-fetch` client 加 middleware：`x-request-id`、錯誤映射、`credentials: omit`。
- generated 檔禁止手改；CI 比對是否有 diff。
- WebSocket event 不在 OpenAPI；用 `src/api/events.ts` 的 discriminated union，欄位與 CORE event 對齊。

### 7.2 圖表

- Chart.js 只註冊需要的 controller／element／scale，避免整包。
- Gantt／timeline 用 SVG，不引入 D3。
- 每頁的圖是「操作後的結果」，不是只有圖沒有操作。
- 大型表格先不虛擬化；超過 1,000 row 再評估 `@tanstack/react-virtual`。

### 7.3 表單

- 先用 controlled components；command 表單不複雜。
- 不做 optimistic update；送出後顯示 pending，等 event。
- 錯誤碼對應固定文案；details 放 inspector，不塞進 toast。
- 不在 client 做遊戲規則驗證，只做輸入格式檢查。

### 7.4 CSS

- **CSS Modules + global tokens**；不引入 Tailwind。
- 理由：terminal UI 需要精確密度與自訂 panel，不想要 utility class 噪音；CSS Modules 讓每個元件區域化。
- 不引入 Ant Design／MUI／Arco／Semi／TDesign／Element Plus 等大型 UI kit；避免 SaaS 外觀與 bundle 膨脹。
- Icon 用 inline SVG；不引入 icon library。

## 9. Bundle 與效能

- 初始 bundle 目標 **< 300 KB gzip**（不含 lazy chart chunk）。
- Chart.js 只在 `/food/*`、`/os/*`、`/ops` 等需要圖表的 route 載入。
- `React.lazy` 切 9 頁；shell 保持小。
- 事件更新以局部 component 為主；不要每 event 重繪整個 app。
- 不在 FE 做大量計算；模擬與演算法結果由 CORE 提供。

## 11. 不採用

| 候選 | 不採用原因 |
|---|---|
| Next.js | 本機 SPA，不需要 SSR／SEO／server action；多一層 server |
| Vue／Svelte | 團隊與文件以 React 為基準；沒有換的理由 |
| Ant Design／MUI | SaaS 外觀、bundle 大；Ant Design 還是中國大陸主導 |
| Tailwind | 終端 UI 需要精確自訂；utility 會讓 markup 難讀 |
| Redux | 過重；TanStack Query + Zustand 足夠 |
| GraphQL | CORE 已是 REST／OpenAPI；不需要另一套協議 |
| Socket.io | CORE 是原生 WebSocket；不需要額外協議 |
| D3 | Chart.js + SVG 已足夠；D3 對本專案過重 |
| xterm.js | 不是真 terminal；自建 LogStream 更符合需求 |
| Storybook | 先不做；用 Vitest + RTL + 實際頁面 |
| Electron／Tauri | 課程要求瀏覽器網站；不需要桌面殼 |
| Godot／Unity／Phaser | 不是本專案前端方向 |
