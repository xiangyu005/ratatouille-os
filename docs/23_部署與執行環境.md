## 1. 版本需求

| 元件 | 版本 | 來源 |

| Python | **3.14.10** | `.python-version`、`pyproject.toml` |
| uv | 0.13.6+ | 環境與鎖定（`uv.lock`、`ai/uv.lock`） |

版本以鎖檔為準；`uv sync --locked` 失敗代表鎖檔與 `pyproject.toml` 不一致，不要用 `--upgrade` 掩蓋。

## 2. 環境與目錄

```text
ratatouille-os/
├─ .venv/          # CORE（Python 主環境）
├─ ai/.venv/       # AI 依賴環境，與 CORE 分開
├─ data/core/      # core.sqlite（不進 git）
├─ data/ai/        # rag.sqlite、vectors.faiss、bm25s/（不進 git）
├─ core/  ai/  scripts/  docs/
└─ .env.example    # 環境變數範本（複製成 .env 使用）
```

- **兩個 venv 不混用。** CORE 只需要 `fastapi`、`uvicorn`、`pydantic`、`websockets`；AI 的 FAISS／BM25S／Numba／PDF 依賴只存在 `ai/.venv`，不得進 CORE 的 `pyproject.toml`（`18-01`）。
- `websockets` 是 CORE 的正式依賴，不是選配：少了它，uvicorn 會回
  `WARNING: No supported WebSocket library detected`、`/ws/events` 直接 404。
  Starlette 的 `TestClient` 在 in-process 處理 WS，所以測試不會抓到這個問題。
- `frontend/` 有自己的 `node_modules` 與 `package-lock.json`，不進 git 的只有 `node_modules/`、`dist/`。
- `.env` 不進 git；只有 `.env.example` 進版控。

## 4. 啟動

### 4.1 開發（建議）

```powershell
uv sync --locked
uv run python scripts\run_core.py
```

預設 `http://127.0.0.1:8001`。`run_core.py` 會建立 app 並用 uvicorn 啟動，讀 `CORE_HOST`／`CORE_PORT`／`CORE_LOG_LEVEL`。

### 4.2 直接指定 app

```powershell
uv run uvicorn core.api.main:app --host 127.0.0.1 --port 8001
uv run uvicorn --factory core.api.app:create_app --host 127.0.0.1 --port 8001
```

`core/api/main.py` 只建立 app 實例，避免 import 時就建 DB；`--factory` 形式適合測試與多種 DB 路徑。

### 4.3 單 worker 限制

**目前必須用單一 worker。** 原因：

1. SQLite 只允許單寫入者，多個 worker 會互相搶鎖（`busy_timeout=5000` 只是等待，不是解法）。
2. `WorldEngine` 以 `asyncio.Lock` 序列化 command，而 `Store` 用**一條釘住的連線**加執行緒鎖；跨程序共用同一檔案會讓 WAL 檢查點與快取行為難以預測。

多 worker／多程序的行為尚未驗證，列在 `24` 的待驗證清單。要水平擴充時，應先改成單一寫入者服務（例如一寫多讀或外部隊列），不是直接加 `--workers`。

### 4.4 前端（dev server）

```powershell
cd frontend
npm install --legacy-peer-deps
npm run dev        # http://127.0.0.1:5173
```

- CORE 必須先起在 `127.0.0.1:8001`；FE 直接連線，靠 CORE 的 `CORE_CORS_ORIGINS` 放行 5173。
- 位址可用 `frontend/.env.local` 的 `VITE_CORE_BASE` 覆寫。
- `npm install` 加 `--legacy-peer-deps` 是必要的：`openapi-typescript` 的 peer 仍宣告 `typescript ^5`（TS 版本決策見 `22-01` §2 註）。
- 契約變更後要跑 `npm run gen:api` 重生 `openapi.json` 與 `src/api/schema.d.ts`，兩個檔案都要提交。

## 5. 資料檔

| 檔案 | 說明 |
|---|---|
| `data/core/core.sqlite` | 世界、事件、snapshot、idempotency、存檔；**唯一 authoritative** |
| `data/core/core.sqlite-wal`／`-shm` | WAL 檔；服務執行中會存在（連線釘住，所以不會歸零） |
| `data/ai/rag.sqlite` | AI metadata（AI 服務本體尚未實作） |

- 這些檔案都不進 git（`.gitignore` 已排除）。
- 服務執行時**不要**直接複製 `.sqlite` 當備份，會拿到不一致的快照；見 §7。

## 6. 測試

```powershell
uv run pytest                      # CORE，預設 37 個測試
cd ai; uv run pytest               # AI DB（9 個測試）
cd ai; uv run python smoke.py      # AI 依賴發煙
cd ai; uv run python lmstudio_smoke.py   # 需先開 LM Studio 並載入模型
cd frontend; npm run lint; npm run typecheck; npm run test; npm run build   # FE 6 個測試
```

- CORE 測試不需要 AI venv，也不需要網路。
- Windows 上若 pytest 的暫存目錄被其他程序鎖住，可指定工作區內的路徑：`uv run pytest --basetemp=.tmp\pytest`。
- 測試使用暫存 DB，不會碰到 `data/core/core.sqlite`。

## 7. 升級與備份

### 7.1 Schema 升級

1. 先停服務。
2. 備份 `core.sqlite` 與 `-wal`／`-shm`（見 §7.2）。
3. 啟動新版；`Store.initialize()` 會以 `CREATE TABLE IF NOT EXISTS` 補新表並更新 `meta.schema_version`。
4. 確認 `/api/v1/meta` 的 `schema_version` 符合預期。

目前版本：`schema_version=2`（新增 `saves` 表）。migration 只向前、不支援降版。

> **未實作：** `20` §8 要求「DB 版本高於程式支援版本時拒絕啟動」，目前 `Store` 只做 `CREATE TABLE IF NOT EXISTS` 與更新 `meta.schema_version`，沒有版本過高的檢查。要降版或換回舊程式前，必須自行確認 schema 相容。

### 7.2 備份

- 服務停止後直接複製 `core.sqlite`（此時 WAL 已合併）。
- 服務執行中要先做檢查點，再複製三個檔案：

```powershell
# 於服務執行中，用另一個連線觸發檢查點
uv run python -c "import sqlite3;c=sqlite3.connect('data/core/core.sqlite');c.execute('PRAGMA wal_checkpoint(TRUNCATE)');c.close()"
Copy-Item data/core/core.sqlite* backup\ -Force
```

- 遊戲內的存檔點請用 `POST /api/v1/save`，與檔案備份是兩件事：前者是玩家進度，後者是資料安全（`08-04`）。

### 7.3 還原

停服務 → 覆蓋 `core.sqlite`（並刪除舊的 `-wal`／`-shm`）→ 啟動 → `GET /api/v1/snapshot` 確認 `state_version`。

## 8. 健康檢查與監控

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod http://127.0.0.1:8001/api/v1/meta
Invoke-RestMethod http://127.0.0.1:8001/api/v1/snapshot
```

- `/health` 只反映 CORE 自己，不檢查 AI／FE（`17` §6.2）。
- 延遲與 tick 預算的檢查方式見 `21` §4；超過 5 ms 要記到 `24`。
- 日誌由 uvicorn 輸出；`CORE_LOG_LEVEL=warning` 可降低開發噪音。

## 10. 常見問題

| 現象 | 原因與處理 |
|---|---|
| 啟動時 `address already in use` | 8001 被佔用；改 `CORE_PORT` 或關掉舊程序 |
| `database is locked` | 多個程序同時寫同一顆 DB；確認只跑一個 CORE |
| FE 被 CORS 擋 | 把 FE 來源加進 `CORE_CORS_ORIGINS`（含協定與埠） |
| `/docs` 404 | `ENABLE_DOCS` 預設 0；需要時設為 1 |
| 測試找不到暫存目錄 | 見 §6，用 `--basetemp` 指到工作區內 |
| 讀檔後事件編號看起來跳號 | 讀檔不重播事件，`last_event_id` 沿用存檔值；新事件從該點繼續 |
| `/ws/events` 回 404、log 出現 `No supported WebSocket library detected` | CORE venv 少了 `websockets`；`uv sync --locked` 後重啟（見 §1） |
| FE 白畫面、console 有 CORS 或 fetch 錯誤 | 確認 CORE 在 8001、`CORE_CORS_ORIGINS` 含 `http://127.0.0.1:5173` |
| `npm install` 因 peer dependency 失敗 | 加 `--legacy-peer-deps`（`openapi-typescript` 宣告 `typescript ^5`） |
