## 1. 邊界

- FE 與 AI **只能**經 CORE API 操作世界；不得直接開 `core.sqlite`，也不得自行裁決世界狀態（`17` I1）。
- CORE 不依賴 FE／AI 才能啟動或回應；FE／AI 全部關閉時，`/health`、`/api/v1/*` 仍須可用。
- 破壞性變更才升版（`/api/v2`）；新增欄位屬於相容變更，FE 必須忽略未知欄位。

## 2. 通則

| 項目 | 規則 |
|---|---|
| 前綴 | `/api/v1`；`/health` 不帶前綴 |
| 命名 | JSON 一律 snake_case |
| 時間 | `sim_time` 是遊戲秒（整數）；`created_at` 是 UTC ISO-8601 |
| `request_id` | 每個 response 都帶，且與 `x-request-id` header 一致；客戶端可自帶 `x-request-id` |
| 錯誤 | 固定 `code`＋`message`＋`details`；不得把 Python traceback 丟給 FE |
| 認證 | 目前沒有；服務只綁 `127.0.0.1`，由部署層限制存取 |
| CORS | 由 `CORE_CORS_ORIGINS` 控制，預設 `http://127.0.0.1:5173`、`http://localhost:5173` |
| OpenAPI | 預設關閉；`ENABLE_DOCS=1` 時 `/docs`、`/openapi.json` 才存在 |
| 冪等 | 所有 mutation 都必須帶 `idempotency_key` |

## 3. REST 端點

| Method | Path | 成功碼 | 用途 |
|---|---|---|---|
| GET | `/health` | 200 | CORE 自身健康，不檢查 AI／FE |
| GET | `/api/v1/meta` | 200 | 版本、schema_version、演算法清單、可用策略 |
| GET | `/api/v1/snapshot` | 200 | 世界 snapshot；可帶 `since_event_id` 取增量 |
| GET | `/api/v1/events` | 200 | 事件查詢（分頁、type、時間範圍） |
| GET | `/api/v1/tasks` | 200 | 任務／佇列（排程頁） |
| GET | `/api/v1/resources` | 200 | worker／station（監控頁） |
| POST | `/api/v1/commands` | 202 | 唯一 mutation 入口 |
| POST | `/api/v1/save` | 201 | 手動存檔 |
| GET | `/api/v1/saves` | 200 | 存檔清單（不含 state 內容） |
| POST | `/api/v1/load` | 200 | 讀取指定或最近存檔 |
| WS | `/ws/events` | 101 | 事件、snapshot、心跳 |

### 3.1 `GET /health`

```json
{"request_id": "…", "status": "ok", "service": "core", "version": "0.1.0",
 "sim_time": 120, "state_version": 7}
```

### 3.2 `GET /api/v1/meta`

```json
{"request_id": "…", "service": "core", "version": "0.1.0", "schema_version": 2,
 "algorithms": [{"name": "fcfs", "label": "FCFS", "assignable": true},
                {"name": "srtf", "label": "SRTF", "assignable": false}],
 "policies": ["fcfs", "priority_aging", "sjf"],
 "default_policy": "fcfs"}
```

`algorithms` 是全部演算法；`policies` 是**可驅動世界指派**的子集（`21` §2）。

### 3.3 `GET /api/v1/snapshot`

| 參數 | 型別 | 說明 |
|---|---|---|
| `since_event_id` | int ≥ 0，選填 | 給定時回傳此 id 之後的事件，供重連補齊 |
| `event_limit` | int 1–1000，預設 500 | 增量事件的數量上限 |

```json
{"request_id": "…", "state": {"sim_time": 30, "version": 4, "seed": 42,
  "policy": "fcfs", "next_task_seq": 3, "last_event_id": 9,
  "tasks": {"T-0001": {"id": "T-0001", "name": "Soup", "burst_seconds": 4,
                       "status": "running", "remaining_seconds": 4,
                       "priority": 0, "enqueued_at": 0, "started_at": 0,
                       "finished_at": null, "worker_id": "W-1",
                       "station_id": "S-1"}},
  "workers": {"W-1": {"id": "W-1", "name": "Worker 1", "status": "busy",
                      "task_id": "T-0001"}},
  "stations": {"S-1": {"id": "S-1", "name": "Prep Station", "status": "busy",
                       "task_id": "T-0001"}}},
 "last_event_id": 9, "state_version": 4,
 "events": null}
```

帶 `since_event_id` 時 `events` 是陣列（可能是空陣列），不是 `null`；FE 以此判斷是「全量」還是「增量」。

### 3.4 `GET /api/v1/events`

| 參數 | 型別 | 說明 |
|---|---|---|
| `after_id` | int ≥ 0，預設 0 | 只回傳 id 大於此值的事件 |
| `limit` | int 1–1000，預設 100 | 上限 |
| `type` | str ≤ 64，選填 | 事件類型完全比對 |
| `from_sim_time`／`to_sim_time` | int ≥ 0，選填 | `sim_time` 閉區間 |

```json
{"request_id": "…", "last_event_id": 9,
 "events": [{"event_id": 8, "type": "TASK_ENQUEUED", "sim_time": 0,
             "state_version": 3, "payload": {"task": {"id": "T-0002"}},
             "causation_id": "req-…", "correlation_id": "T-0002",
             "created_at": "2026-11-02T10:46:56.067Z"}]}
```

事件永遠依 `event_id` 遞增回傳；分頁請用 `after_id=最後一筆的 event_id`，不要用 offset。

### 3.5 `GET /api/v1/tasks`、`GET /api/v1/resources`

```json
{"request_id": "…", "tasks": [ … ], "sim_time": 30, "state_version": 4}
{"request_id": "…", "workers": [ … ], "stations": [ … ],
 "sim_time": 30, "state_version": 4}
```

陣列版本依 id 排序，內容與 snapshot 內的物件相同。

### 3.6 `POST /api/v1/commands`

```json
{"command": "ENQUEUE_TASK",
 "args": {"name": "Soup", "burst_seconds": 4, "priority": 0},
 "idempotency_key": "fe-7f3c1a2e",
 "client": "fe"}
```

```json
{"request_id": "…", "accepted": true, "event_ids": [10], "state_version": 5,
 "error": null, "cached": false}
```

- `client` 只作紀錄，預設 `unknown`。
- 重送同一個 `idempotency_key` 會回傳當初的結果並帶 `"cached": true`，**不會**再套用一次。
- 被拒絕的 command 不會寫入任何 event 或 snapshot。

可用 command：

| Command | args | 行為 |
|---|---|---|
| `ENQUEUE_TASK` | `burst_seconds`（必填，≥1）、`name`、`priority` | 建立 `queued` 工作，id 由 `next_task_seq` 產生 |
| `ASSIGN_TASK` | `worker_id`、`task_id`、`station_id?` | 非搶佔指派；未給 station 時挑 id 最小的空閒站 |
| `SCHEDULE_QUEUE` | `policy?` | 依策略把 queued 工作配給 idle worker／free station |
| `ADVANCE_TIME` | `seconds`（必填，≥1） | 推進模擬時間，完成到期工作 |
| `SET_POLICY` | `policy` | 設定預設策略（僅限可指派策略） |

事件類型：`TASK_ENQUEUED`、`WORKER_ASSIGNED`、`TASK_STARTED`、`QUEUE_SCHEDULED`、`TASK_COMPLETED`、`TIME_ADVANCED`、`POLICY_CHANGED`。

### 3.7 存檔

```json
POST /api/v1/save   {"label": "before-cooking"}
201 {"request_id": "…", "save_id": 3, "schema_version": 2, "state_version": 12,
     "last_event_id": 44, "label": "before-cooking",
     "checksum": "5f2c…13fb", "created_at": "2026-11-02T10:46:56.067Z"}
```

```json
GET  /api/v1/saves?limit=50
200  {"request_id": "…", "saves": [{"save_id": 3, "schema_version": 2,
      "state_version": 12, "last_event_id": 44, "label": "before-cooking",
      "checksum": "5f2c…13fb", "created_at": "…"}]}
```

- `save_id` 由 DB 遞增，越新越大；清單依 `save_id` 由新到舊。
- 不提供刪除；存檔只增不減（`08-04` 不提供玩家歷史回溯選單）。

### 3.8 `POST /api/v1/load`

```json
POST /api/v1/load   {"save_id": 3}
200 {"request_id": "…", "loaded": true, "save_id": 3, "state_version": 12,
     "last_event_id": 44, "label": "before-cooking"}
```

- 省略 `save_id` 或帶 `{}` 時讀取最新存檔。
- 讀檔前驗證 `checksum`；不符回 409 `SAVE_CORRUPTED`。
- **不重播已結算事件**：存檔本身已是最終結果，讀檔不會重新扣料或重算收入。
- 讀檔後會對所有 WS 客戶端廣播 `SNAPSHOT`（`reason=save_loaded`），FE 應以此整份替換本地狀態。
- 讀檔不會回復 idempotency 紀錄；已用過的 key 仍回傳當初的結果。

## 4. 錯誤契約

```json
{"request_id": "…", "accepted": false, "event_ids": [], "state_version": 5,
 "error": {"code": "WORKER_BUSY", "message": "Worker W-1 is busy", "details": {}},
 "cached": false}
```

| code | HTTP | 觸發條件 |
|---|---|---|
| `MISSING_ARGUMENT` | 422 | 必填 args 缺少 |
| `INVALID_ARGUMENT` | 422 | args 型別或範圍錯誤 |
| `UNKNOWN_COMMAND` | 422 | 未知 command；`details.known` 列出可用者 |
| `POLICY_NOT_ASSIGNABLE` | 422 | 用搶佔式策略驅動世界指派；`details.assignable` 列出可用者 |
| `WORKER_NOT_FOUND` | 404 | worker 不存在 |
| `TASK_NOT_FOUND` | 404 | task 不存在 |
| `STATION_NOT_FOUND` | 404 | 指定的 station 不存在 |
| `WORKER_BUSY` | 409 | worker 不是 idle |
| `TASK_NOT_QUEUED` | 409 | task 不是 queued |
| `STATION_BUSY` | 409 | 指定的 station 不是 free |
| `NO_FREE_STATION` | 409 | 沒有空閒 station |
| `SAVE_NOT_FOUND` | 404 | 指定存檔不存在，或完全沒有存檔 |
| `SAVE_CORRUPTED` | 409 | checksum 驗證失敗 |

**已知缺口：** 請求 body 不符合 Pydantic schema 時，FastAPI 會回自己的 `{"detail": [...]}` 422，沒有 `request_id` 也沒有 `code`。FE 目前需同時處理兩種 422；補齊自訂 handler 是待辦（§8）。

## 5. WebSocket

連線：`ws://127.0.0.1:8001/ws/events`。

| 訊息 | 時機 | 內容 |
|---|---|---|
| `SNAPSHOT` | 連線後立即、讀檔後 | `type`、`state`、`last_event_id`、`state_version`（讀檔時多 `reason: "save_loaded"`） |
| 事件 | 每次 command 成功 | `event_id`、`type`、`sim_time`、`state_version`、`payload`、`causation_id`、`correlation_id` |
| `PING` | 15 秒無事件 | `type`、`sim_time` |

- 事件順序以 `event_id` 為準；FE 必須能處理重複與缺口。
- 重連流程：收到 `SNAPSHOT` 後，用 `GET /api/v1/snapshot?since_event_id=<last_event_id>` 補齊缺漏；不要只靠 WS。
- 慢客戶端佇列上限 256；滿了會丟掉該客戶端最舊的事件，**不會**阻塞世界。被丟事件時 FE 只能用 `since_event_id` 重新同步。
- 不每幀重傳整個 world；snapshot ＋ 增量事件是唯一模式（`17` §6.4）。

## 6. 契約同步

```text
core Pydantic models → OpenAPI（FastAPI）→ scripts/generate_types.py
  → frontend/src/api/schema.d.ts → ai/core_client
```

- **現況：`scripts/generate_types.py` 尚未建立。** 目前 FE／AI 需人工依本文件與 `ENABLE_DOCS=1` 的 `/openapi.json` 對接。
- 預計流程：CI 產生 types 後與 repo 內檔案比對，不一致即失敗；generated 檔禁止手改。
- `schemas.py` 是契約的單一來源；改欄位要同步本文件與 `20`。
